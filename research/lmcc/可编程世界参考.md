## 一、结论先行

### 要抄的五条

| # | 机制 | 出处 | 我们怎么落 |
|---|---|---|---|
| 1 | **延迟是元件的显式参数**，不是隐含属性 | 红石中继器有 1–4 档延迟，顶部火把间距就是时间 | 每个处理元件带可编辑延迟，且参数**在世界里可见**，不藏进 GUI |
| 2 | **统一操作成本模型**，且成本能被程序读到 | 《编程农场》：改世界固定 200 ops，只读 1 op | token 即电力（原 spec §6）照此做：改一次世界与读一次状态定价不同，且这个数字能被学员代码读到；一举兼作优化指标、行为激励与步骤面板上的标量 |
| 3 | **可观测性进内核**，不是外挂 | 红石的反面教训：社区被迫自写 Inspector / Signal Visualizer | 内建一组：`read` / `trace`（波形）/ `watch`（订阅）/ `step`（真单步）/ `diff` / `export_netlist`。另参照 ONI 的 Automation Overlay（专用叠加视图 + 每个端口明写绿/红语义）与 Factorio 的悬停即探针 + Display panel |
| 4 | **权威记录与画面产物分离**：权威 = 工具调用序列 + 种子 + 版本哈希；轨道是带 hash 的派生产物 | Dreams 2.58 的 Physics Mode 官方把物理烘焙进轨道；F 组据此建议 | 步记录为权威，轨道由它驱动且附 hash 可校验——**方向不能反**（不能拿轨道当事实源去反推过程） |
| 5 | **隐式状态必须进快照**，并给状态指纹 | The Powder Toy：仿真 RNG 状态入档、`ensureDeterminism` 强制气压场与环境热入档、`sim.hash()` 断言两次运行一致、快照 delta 连 RNG 一起回滚 | 世界快照必须包含仿真读到的**全部**状态；给一个状态指纹用于断言两次运行一致 |

### 不要碰的三条

| # | 坑 | 出处 | 为什么 |
|---|---|---|---|
| 1 | **物理耦合逻辑时序** | 红石的准连接性、0-tick 脉冲、软硬充能之分、重配置不触发更新 | 这些全是引擎副产品，也是红石最难学的部分。物理→逻辑的耦合必须**单向且显式** |
| 2 | **物理步进挂在帧率或时间缩放上** | Besiege：`timescale>100%` 或 `<30fps` 时计算变粗糙、结果更不可预测 | 推论：**慢放绝不能通过放大物理步长实现**，只能靠取帧策略 |
| 3 | **一上来就给排行榜** | Turing Complete 官方 FAQ：过早开放会让玩家"不找到最优解就不前进"，新手抄最优解后"觉得自己蠢并卡住" | 反例是 Shenzhen I/O v1.1「从第一关就能优化」，同一机制两位作者给出相反答案——**这是必须自测的变量** |

### 改造后抄

- **红石的"少量原语 + 涌现"**：我们不需要图灵完备，需要的是可诊断。原语收在 11 种方块，涌现交给学员的装配。
- **《编程农场》的解锁设计**：语言表达力与世界内容**同步扩展**（变量→循环→函数→列表→字典，同时世界解锁新地块）。限制即教学，但**必须同时给解锁路径**，否则会写代码的学员前 30 分钟就流失。我们的一级→二级→三级粒度与之同构。
- **离散信号可视化**：Mindustry 与 Shapez 2 都没有单步与断点，只能用变量面板与连线颜色替代。而我们的"信号"（工具调用的参数与返回值）**不在世界里**，所以步骤带是必须自建的东西，没有现成做法可抄。

## 二、逐份报告的要点

### D · 红石

- 图灵完备性来自**四个正交原语**（反相器、导线、锁存、时钟）加一个显式延迟参数；2023 年一篇学位论文用 Minsky 寄存器机给出正式证明。中继器一身三职：二极管 + 信号再生 + 4 档延迟 + 可锁存的一位存储。
- 代阶是时间与面积的双重离散化：单线 15 格必衰减、每 15 格必须插中继器（≥2 game ticks）、火把 3 秒内被迫熄灭 8 次即烧毁、调度 tick 上限 65,536/tick。CHUNGUS 2 有四级流水线仍只有 **1 Hz**；一个高 250 格的图形计算器在 20 倍加速下画一条直线要 **2.5 小时**。
- **可观测性是它彻底失败的地方**：比较器输出数值、方块充能、单 tick 脉冲全部不可见，执行器是 1-bit 只读；官方与教育版从未做过红石可视化。CHUNGUS 2 造了 7 个月，最终只留一个程序计数器数码管。
- **官方教育版"能写不能读"**：MakeCode 能放置元件、能用 `agent.detect` 判方块种类，但**没有任何读取红石信号强度的 API**，连"红石灯亮没亮"都测不到。这既是我们的差异位，也意味着这条路上没有现成模板可抄。
- 建议：默认布尔，**模拟量做成连线上可见的显式端口类型**；`export_netlist` 性价比最高——让 Agent 读网表而不是读方块。
- 环境限制：`web_search` 全程 402 不可用；`education.minecraft.net` 全站 404，`reddit.com`、`archive.org` 不可达，社区抱怨帖只能做到标题级。

### E · 编程游戏

- 《编程农场》：无关卡、连续曲线解锁；开局只能在单格收草。
- 可观测性分层做法：每步结构化记录（参数 / 返回码 / 成本）、**零动画调试输出**（打印与快速打印刻意分开）、状态面板自动刷新、世界内锚点、限速、断点、探针。Screeps 官方警告"返回成功 ≠ 世界已改变"，须并排调用日志与世界 diff。
- **FWR 玩家原话**：用 AI 帮自己写代码"像在射击游戏里开自瞄——没有挑战，也没有乐趣"。结论：乐趣要从"写代码"迁移到"**设计流程 + 判断 Agent 对错 + 诊断失败**"。
- 三处事实更正（供后续引用）：Human Resource Machine 与 7 Billion Humans 是 Tomorrow Corporation 的作品，不是 Zachtronics；Mindustry 的 mlog 是 v6 引入；Shapez 2 **没有**编程层，逻辑只有 6 个门。
- 环境限制：`web_search` 中途 402 失效，Steam、Reddit、Fandom、Wikipedia 不可达；Mindustry / Shapez 2 / Gladiabots / Autonauts 的"玩家最复杂作品"与"批评原话"系统性缺失，已逐条标注。

### F · 物理沙盒

- **唯一真正同时做到物理与可复现的是 The Powder Toy**：仿真专用 RNG 状态可序列化入档；`ensureDeterminism` 强制把气压场与环境热这类隐性状态入档；`sim.hash()` 状态指纹可断言；撤销 = 快照 + delta 且 delta 带 RNG 与帧计数；仿真 FPS cap 与渲染 draw cap 解耦；支持逐帧步进；粒子更新单线程。
- **刚体侧无人解决**：Besiege 官方论坛的字面证据是同设计不同结果；Algodoo 官方承认仿真速度与 CPU 性能耦合；Roblox 不承诺跨客户端确定性。
- **Dreams 2.58 的 Physics Mode** 把物理与逻辑驱动的运动烘焙进 Action Recorder 轨道，且做成**可选模式**而非唯一路径——我们的烘焙方案有商业先例。
- 三大坑：① 没进快照的隐式状态；② 物理步进挂在帧率与时间缩放上；③ 状态持久化策略不统一（Scrap Mechanic 的 Timer 状态跨存档保留，而逻辑门与开关状态会重置）。
- Stationeers 的 IC10 是游戏内真汇编：151 条助记符、128 行 × 90 字符、128 行/tick 自动暂停、**无事件驱动只能轮询**、寄存器与栈永不自动清零；调试靠写 `Setting` 参数与 jal 断点。

## 三、并入 spec v4 的修改点

| 位置 | 改法 |
|---|---|
| §5 步记录 | 权威记录 = **工具调用序列 + 种子 + 版本哈希**；轨道改为由它驱动、附 hash 的派生产物，方向不可反 |
| §5 / §7.1 | 世界快照必须包含仿真读到的全部状态（含物理隐性状态：场、热、RNG），并给状态指纹用于断言 |
| §7.1 | 补一句：**慢放不得通过放大物理步长实现**，只能靠取帧策略 |
| §7.1 | 物理→逻辑的耦合必须单向且显式；不得继承红石式的引擎副产品（准连接性、0-tick） |
| §7.2 | 工具面补一组可观测性工具：`read` / `trace` / `watch` / `step` / `diff` / `export_netlist`；并明写每个端口的语义（参照 ONI 的绿/红） |
| §7.2 / §8 | 成本模型：改世界与只读查询定价不同，且该数字可被学员代码读到（参照《编程农场》的 200 : 1） |
| §6 / 方块体系 | 新增**播放器方块**（家族二·幕布），视频与动手合到一处 |
| 关卡与进度 | 解锁顺序参照《编程农场》：语言表达力与世界内容同步扩展，且必须给解锁路径；排行榜延后开放，是否开放需自测 |

## 五、修订（2026-09-13 晚）

用户裁决：**"同一份设计跑两次结果不同好像并没有关系"**，项目需要的只是一套**勉强好用、像 MC 与围攻**的物理。据此撤销本文第一节的其中两条：

| 原条目 | 处置 |
|---|---|
| 要抄 #4「权威记录 = 工具调用序列 + 种子 + 版本哈希，轨道是带 hash 的派生产物」 | **保留前半，撤销后半**。步记录仍是唯一权威（理由从"确定性"换成"**避免两个真相源**"）；`trackHash`、哈希校验、`stateHash` 全部作废——没有确定性要保，就没有指纹要断言 |
| 要抄 #5「隐式状态必须进快照」 | **撤销**。它唯一的作用是让两次运行可比对；既然不要求两次一致，隐性状态就不必入档 |
| 不要碰 #2「物理步进挂在帧率或时间缩放上」（Besiege 的坑） | **保留**，但理由换成**保真**：放大步长会让东西穿透、堆叠炸开，画面变糙。与可复现无关 |

**撤销后仍然成立的**（这些与确定性无关，各有别的理由）：

- 延迟是元件的显式参数 —— 教学需要
- 统一操作成本模型（改世界贵、只读便宜，且数字可被代码读到）—— 激励与优化指标需要
- 可观测性进内核（`read`/`trace`/`watch`/`step`/`diff`/`export_netlist`）—— 红石的反面教训，教学需要
- 可复现三件套里的 **LLM 响应缓存** —— 理由是**成本**
- 物理→逻辑的耦合单向且显式 —— 理由是**可读**（红石的准连接性、0-tick 是反面教材）

**新增的物理标准**（写进 spec §7.1）：不追求精确、不追求可复现，只要手感不崩；对标《我的世界》与《围攻》。烘焙降为按需可选，只为"同一段要出两个机位并做剪辑拼接"这一种情况；默认路径是一镜到底或录 wide 后期裁切。
