# 2026-09-13 · 沙盒数据模型与六棱柱排布

> 重大决策与重大 bug 记录。背景 / 备选 / 选择 / 后果。

## 背景

视觉验证做到第六版时，用户指出：「它整体并没有涉及标准方块的大小，所以它根本就不是沙盒」。

这个判断是对的。此前几版把世界做成了**高度场渲染出来的景观**：每根柱子只有"长多高"，没有"第几层第几格"。世界不可寻址，就不存在放置与破坏——那不是沙盒，是风景。

同时用户澄清了三条优先级：**它应该是类似《我的世界》的开放游戏**；**线条应该非常明晰**；**画质和光影是后加的内容**。

## 备选

**A. 继续在高度场上修画面。** 保持现有结构，只调曝光、雾、配色。
**B. 改成单元字典 + 渲染视图分离。** 世界是 `(q, r, level) → 单元` 的字典，渲染只读它。
**C. 回到立方体体素。** 直接用成熟的方块体素方案。

## 选择

**B。** 并且保留六棱柱作为标准单元（不选 C）。

理由：

- 沙盒的本质是**离散、可寻址、可增删的标准单元**，不是某个特定的形状。六棱柱同样能无缝铺满空间，也同样是标准单元——但它和方块世界长相完全不同，避开了抄袭问题。
- 高度场是"生成器"，字典是"世界"。前者只能看，后者能改。
- 渲染与数据分离之后，存档、撤销、多人同步都只需要动字典。

## 后果

**已发生**

- `_voxels: Dictionary[Vector3i(q,r,level)] -> Color` 成为唯一事实来源；`_render_voxels()` 只读它
- 世界规模 120×120，单元 86,886 个，**生成 + 自检 0.6 秒**
- 「破坏」与「放置」都做成了真实操作并写进断言：削平一条 31×3 的走廊到 `ROAD_LEVEL`（断言上方无残留），在路旁搭一座 3×3×2 = 18 单元的工坊（断言 18 个单元全在），四角各一盏自发光灯单元
- 相机改为**站在世界里面往外看**（眼高 1.7），不再是看模型的机位

**修掉一个隐蔽的根因 bug**

地面每个三岔口都有规律的黑三角洞，先后试过调半径、调描边，都没解决。真正原因是**六边形排布公式与网格朝向不匹配**：

- Godot 的 `CylinderMesh` 生成的是**尖顶**六边形（顶点朝 ±Z）
- 代码里用的却是**平顶**排布公式（`x = 1.5·R·q`）
- 两者错配 → 相邻单元错位 → 每个三岔口裂出三角洞

改成尖顶公式（`x = sqrt(3)·R·(q + 0.5·(r%2))`）后洞全部消失，地面成为连续面，六边形格线反而变得非常清晰——**这正是用户要的"线条明晰"**。

**需要承担**

- 120×120 的世界有 86,886 个单元，其中绝大多数埋在地下、永远不会被看见。当前不做遮挡剔除，先跑通结构；真做开放世界时按区块（chunk）分块与剔除。
- 自发光单元要单独一个 `MultiMesh`（per-instance color 改不了材质），世界因此有两个网格。

**未解决**

- 画质与光影仍未定稿（亮度均值 154，偏高；整体偏"晒白"）。按用户定的优先级，这是**后加项**，结构稳定前不再投入。
- 尚无区块（chunk）与存档格式；放置/破坏只有内存里的字典，重启即失。
