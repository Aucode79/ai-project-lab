# 语义语句与表达式层级

## 背景

Python 源码导入的首版把变量、常量和每个算子都作为默认可见方块。结构过细，简单代码也被摊成流水线。用物理代码行做节点也不稳：一条语句可以跨多行，一行也可以包含多个语句。

## 备选

1. 每个表达式和符号都作为默认可见方块。
2. 每个物理代码行作为默认可见方块。
3. 以语义 `Statement` 为默认可见块；保留内部 `Expression`、`Symbol`、`Scope` 和关系结构，按需展开。

## 选择

选择方案 3 作为**解析、编译与执行追踪的底层结构**。程序由函数模块承载；模块声明函数输入和作用域符号。赋值语句与返回语句使用语义节点，节点引用独立表达式模块；数据边表示变量引用，控制边表示语句顺序。表达式模块保留输入、常量与运算的结构。

语句节点不规定学习者默认看到的画面，也不规定函数模块如何呈现内部结构。面向学习者的递归程序盒与三维内构由[递归程序盒与可见内构](2026-09-23-递归程序盒与可见内构.md)定义。当前导入器仍以语句图直接渲染，是过渡原型。

原始源码片段只作为语句块表面的显示内容，语义由 AST 转出的结构决定。展示文本不进入语义哈希。因而跨行表达式仍是一个语句节点；同一物理行上的多个语句仍各自建模。

本文记录语义语句与表达式层级的结构决策，不登记导入器的当前覆盖范围。Python 导入能力持续扩展；现行支持语法、受限类规则与明确拒绝的语义边界以 [Agent Lab 启动说明](../../tools/lesson/README.md) 为准。该导入器仍不覆盖任意 Python，具体原语的整体验收状态见[程序原语覆盖样例](../20-验收/2026-09-23-程序原语覆盖样例.md)。

## 后果

- 底层表达式与语句结构便于编译、追踪和源码映射；学习者视图可从中生成更高层盒子。
- 内部仍可检查真实的表达式与符号依赖，执行仍由共享模块编译器生成。
- 表面代码文本是 Python 源码；语义节点与关系使用与具体排版无关的结构。
- 添加控制语句时，应将条件与子作用域建成语义子结构，不按源码物理行拆块。
