# 沙盒模块作为可执行代码

日期：2026-09-22。状态：可执行首版已实现，见[验收记录](../20-验收/2026-09-22-可执行Agent沙盒.md)。详细实施与验收以[实施方案](../00-入口/2026-09-22-可执行Agent沙盒实施方案.md)为准。

## 背景

第一课已经接入真实语言模型和运输工具，但组件展示并未决定后端控制循环。用户指出整机与任务世界缺少实际关系，要求补齐完整 Agent、文本读写、世界观测和方块到后端的执行对应。

现有折叠是视图分组，四层源码阅读是展示映射；二者都不等于共享模块定义和可编辑调用关系。本次用户以 Fractal Foundry 的嵌套模块为参考，并明确纠正：模块是可视化代码，递归通过引用自身接口表达。

## 备选

1. 保留独立后端，增加连线与动画。不能满足连接决定真实能力的要求。
2. 只提供固定外层模块。不能满足逐层展开修改内部代码的要求。
3. 以可视化代码定义和接口调用为基础，生成 Python，驱动真实 Agent 与同一沙盒。采用此方案。

## 选择

模块默认共享定义；调用节点引用接口，多层嵌套与递归使用普通函数语义。控制流与数据流分离；展开、收起和摆位不改变程序，编辑后下一次运行使用新结构。

方块为唯一编辑入口。模型调用具体工具，工具后端经 CLI 操作沙盒和文件；连接同时决定模型工具说明与执行端可用绑定。错误、循环、返回与异常完全按生成代码执行，不附加 Agent 专属恢复规则。

观测采用全局公开结构化状态，不以截图或图像识别作为本轮输入。工作目录文件与沙盒文档一一对应，以文件系统为准。对话框继续作为任务入口。

本轮交付完整沙盒系统及预装 Agent，以读取任务单、整理货物、写出报告验收；不重做视频。方案确认后，用户要求亲自完成，现已实现独立 Agent Lab 场景、模块编辑器、共享编译器、运行层与 CLI。三维整机负责程序投影与运行反馈，具名端口编辑在二维模块图中完成。

## 后果

新增模块编译、实际运行映射、递归编辑、CLI 与文档同步；编译器集中在 Python，Godot 调用同一实现，避免维护两套语义。端口 7331/7332 与旧第一课 7321/7322 分离。保留既有图编译和关卡契约，新增格式显式分派，旧演示模板不进入新真实运行路径。

本次规则取代该新 Agent 系统中的固定层数展开、手改 Python 后重排，以及组件仅作为固定后端说明物的设计。现有 demo 与旧文档中的历史行为保持历史标注，不能因方案确认就改称已实现。
