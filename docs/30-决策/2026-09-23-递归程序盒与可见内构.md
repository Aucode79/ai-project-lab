# 递归程序盒与可见内构

## 背景

语句级语义 IR 解决了“物理代码行不是稳定语义单元”的问题，但它只属于解析与执行底层，不能直接充当儿童面对的默认界面。若默认把语句、表达式和符号全部摊开，复杂程序仍会变成难读的图。

《Fractal Foundry》的关键不是把程序切成远、中、近、代码四种抽象视图，而是让可复用的工厂模块真实嵌入更大的工厂：外层空间里能直接看见里面的生产结构；进入模块后，仍是同一套机器、输送线和接口。

当前 Agent Lab 已有模块调用盒与双击钻入；旧方案的普通函数盒没有可见内构，Agent 汇总也依赖 `main`、`agent` 的固定节点摘要。2026-09-23 整机引擎 v2 决策曾规定只在钻入后显示模块内部；本决策取代该边界。2026-09-24 起，`machine_view.gd` 已为 call、statement 和带模块的 return 盒加入直接子模块的三维预览，作为第一版视觉切片。

## 备选

1. 把每个 AST/语句节点直接渲染成独立 3D 物件。
2. 为 Agent、函数等常见组件手工设计固定摘要图。
3. 将语言结构解析为语言无关的程序图，再将函数盒实现为可嵌入的三维子工厂；外层直接呈现紧凑的内部机器与通道，进入后展开同一结构供观察和编辑。

## 选择

选择方案 3。语句 IR 保留为编译、追踪与源码定位的底层表示。面向学习者的表示由程序图投影生成，不要求每条语句都成为默认可见物件。每个函数/模块是一台可复用的子工厂；函数调用是在父工厂里放置该子工厂的实例。

程序图分为三类结构：

- **行为节点**：`Object` 表示可流动的数据值；`State` 表示可存放和更新数据的容器；`Transform` 表示把输入变成输出的操作；`Router` 表示按条件选择路径；`Repeater` 表示重复执行。
- **关系边**：`Channel` 表示数据、执行、调用、工具、消息或事件的流动；关系具有明确来源、目标和端口，不伪装成与行为节点同类的方块。
- **递归盒**：`Group`/函数模块是对子图的命名封装，接口由输入与输出端口定义。它本身不是新的执行行为。父级里显示一个紧凑、可读出内部机器与通道的三维子工厂；双击后沿相同结构进入并放大，不切换到另一种图或另一套交互。

对象、状态、变换、路由、重复是当前视觉原语候选，不要求源语言语法与图形一一对应。函数调用、API、模型和 Agent 工具调用均可表现为带接口的 Transform 或子盒；是否带外部副作用由关系与行为元数据表达。语言解析必须保留源码范围及原始语法结构，确保每个投影都能回到可执行图与源代码。

盒子表面不只是标题或代码标签：从父级视角应看见盒内主要生产单元、数据/控制通道和输入输出口，能凭空间结构理解“东西从哪进、经过什么、从哪出”。当内部结构太复杂时，外层可用真实子图的紧凑排布呈现主要步骤；不能以固定图标替代内部结构。双击使相机进入同一个盒子，提升其空间尺度与可操作性；对象身份、通道连接和布局规则保持一致。距离变化负责取景与可读性，不负责把程序语义改写成远中近摘要。

实现顺序以结构验证为先：用[20 个程序原语覆盖样例](../20-验收/2026-09-23-程序原语覆盖样例.md)覆盖值变换、状态读写、分支、循环、函数嵌套、异常、工具/API 调用和 Agent 观察—行动反馈。对每个程序记录解析覆盖、原语映射、信息丢失、源码回溯与儿童可解释性，并检查嵌入盒能否保留父级可读性、输入输出连接及内部主要流程。无法从结构证据确定含义的部分标成通用操作盒或未知副作用，不用猜测补语义。材质细节不作为该门的通过条件。

## 后果

- `Statement` 是底层语义单元之一，不再等同于默认画面中的最小盒子。
- 每个函数模块需要从真实子图生成可嵌入的内部三维结构；不再依赖针对 `main`/`agent` 的固定节点白名单，也不以标题盒或抽象缩略图代替内构。
- 语义原语、通道边和函数盒分别建模，避免把对象、存储、控制流和分组混成同一层类型。
- Python 导入器当前只支持常量、`+ - *`、局部赋值和末尾 `return`，尚不能覆盖本决策的 20 程序样例门。当前预览只显示直接子模块，不递归压缩更深层结构；盒内预览不可编辑，双击后才进入完整子图。机器形状仍按现有节点类型着色，尚未完成跨 Python 结构的通用语义原语映射。因此这只是视觉起步，不代表递归结构和通用 Python 导入已完成。
- 原决策[语义语句与表达式层级](2026-09-23-语义语句与表达式层级.md)继续约束低层导入与执行结构；[整机引擎 v2](2026-09-23-整机引擎v2-工厂感与三维嵌套.md)中“钻入后才显示模块内部”的边界由本决策替代。
