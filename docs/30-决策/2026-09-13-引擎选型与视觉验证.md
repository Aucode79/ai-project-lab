# 2026-09-13 · 引擎选型与视觉验证

> 重大决策记录。背景 / 备选 / 选择 / 后果。

## 背景

产品要做到「我的世界那种高自由度 + 高光影」，并且要**做成软件发布、学员配置简单**。此前在 Godot 与 three.js 之间反复，一度准备转向 three.js。

同时发现：`ai-project-lab` 的既有实现（Godot 4.7 五屏 + FastAPI sidecar）里有一份已完成的参考实现，而 `D:\rl course\` 是课程工作区，项目混在里面导致上下文串味。

## 备选

**A. 转 three.js。** 理由是网页分发、学员零安装，且 LLM 语料最厚。
**B. 留在 Godot 4。** 理由是引擎级 GI、体素模块、导出即 exe。
**C. 双引擎对比验证。** 同一场景两边各搭一个再决定。

## 选择

**B，留在 Godot 4。** 并且在独立目录 `D:\ai-project-lab\` 重开，把视觉验证作为第一步。

依据是三条诉求与两个引擎的实际能力对比：

| 诉求 | Godot 4 | three.js |
|---|---|---|
| 高光影 | SDFGI / VoxelGI / SSAO / SSIL / 体积雾 / AgX，引擎级内置 | 无引擎级 GI，SSGI 属社区方案，需自拼后处理管线 |
| 体素世界 | 有成熟模块可用（本次未用） | 网格生成、贪婪合并、区块流式、LOD 全自写 |
| 做成软件、配置简单 | 导出即 exe，零依赖 | 需桌面壳或"本地服务 + 浏览器" |

three.js 的真实优势在网页分发，那是另一条产品路线，与「做成软件发布」互斥。

## 后果

**已发生**

- 新建独立目录 `D:\ai-project-lab\`，不再放在课程目录里
- 视觉验证场景跑通：Godot 4.7.2 / Forward+ / Vulkan / RTX 5060，1280×720，13 条断言 PASS，1714 个体素方块
- 画面经三轮迭代定稿。一版偏暗（亮度均值 92.7）且地块悬空露出天空暗半球，左侧一条死黑边；二版提亮加地面后**过度曝光**（均值 164.3，饱和度被冲掉，画面像泡在牛奶里）；三版降 exposure 与环境光、提饱和、给地形加起伏、道具改吸附地表，落到均值 105.3 / 标准差 48.3 / 饱和度 40.5，无过曝无死黑。指标全表见 `docs/20-验收/tests.md`

**需要承担**

- 旧仓库已完成的工作（五屏 UI、3D 知识星图、Designed Failure、smoke 测试）在本项目中是**参考实现**，不能直接依赖
- 引擎策略一旦再变，呈现层要重做一遍

**未解决**

- 画面美观程度**没有自动判据**，当前模型也读不了图，需要人看 `game/shots/spike.png` 拍板
- `Zylann/godot_voxel` 与 Godot 4.7 的兼容性未验证。本次刻意绕开该扩展，只验证光影与体素观感。若后续要真体素世界（可破坏、区块流式），需要单独验证它
- 《产品立项预案 v1.3》缺失，本决策可能与它冲突
