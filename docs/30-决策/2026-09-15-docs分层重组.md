# 2026-09-15 · docs 文档体系分层重组

## 背景

2026-09-15 模块化改造收尾后体检发现文档体系三类债：

1. **结构与入口混杂**：21 篇文档平铺在 `docs/` 根（含 spike 时代的 `01-总览.md`、`02-架构.md`），加 `decisions/` / `modules/` / `superpowers/specs/` 三个子目录；`docs/README.md` 的文档地图与实际不一致。
2. **由文档漂移来的错误陈述**（均为实证核对）：
   - `01-总览.md` 写"目前只有一个 Godot 场景"，实际 38 个 `.tscn`。
   - `02-架构.md` 分层表四行全写"未开始"，且第 42 行写"**不引入物理引擎**"——与 `project.godot` 里的 `Jolt Physics` 直接矛盾。
   - `modules/game-scripts-main.md` 只写 `main.gd`（现 `game/scripts/` 有 14 个模块目录），且四处数字过期：voxel 体积 51MB→实际 129M（且"不入库"只对 `bin/` 成立，其余 33 文件已入库）、6 种方块→7 种、14 条断言→15 条、7 个模型→8 个。
   - 根 `README.md` 只有 37 行且指向一个不存在的会话计划 `plan-sess_b464fd9f-*`。
3. **权威声明打架**：`docs/README.md` 说"设计规格的权威是 `superpowers/specs/` 下那份"并把原 spec 标为"完整的形态重做设计规格"，而 `计划.md` 文档地图说"一律以 v6 为准"——两处对同一件事给出不同结论。

同批清掉的死链（全仓核对，不限于文档内）：
- 3 处代码注释指向**不存在**的决策文件：`flow_base.gd:5`、`level_scene_base.gd:6`、`world_builder.gd:8` 写 `docs/decisions/2026-09-14-场景与流程层去重重构.md`，实际文件名是 `2026-09-15-`（上一轮改造自己引入的 bug）。
- `tools/production/README.md:63` 与 `render_layers.py:11` 指向已迁走的 `game/scenes/components/task_board.gd`。
- 3 篇**现行文档**残留旧绝对路径 `/root/lmcc-research/`：`计划.md`、v6 spec（`sandbox-as-studio-design.md`）、`交互方案.md`——资料已迁入 `research/lmcc/`，三篇均改为 `research/lmcc/…`。（原 spec 与「研究资料落库」ADR 里的旧路径**有意保留**：前者顶部横幅已声明"正文未回改、路径指向 fork 前旧仓库"，后者本身记录的就是那次迁移的源路径。）
- 6 个已退役探针的 `probe_*.gd.uid` 仍被 git 跟踪（`.gd` 已删），另有空目录 `game/scenes/components/`。

## 备选

| 方案 | 做法 | 代价 |
|---|---|---|
| A 轻整理 | 路径全不动，只重写 `docs/README.md` 索引 + 原地修过期内容 | 改动最小；但"根目录混着历史快照与现行契约"这一核心问题没解决，下次仍要为每篇判断时效 |
| B 中等 | 不被代码引用的文档移入子目录；被代码引用的 5 篇专题留根不动 | 零代码改动；但分层只做一半——`互动方案/mini-codex/方块体系/美术方向/测量结果` 5 篇仍散在根，而这 5 篇恰是被代码引用最多、最常被翻的 |
| C 彻底 | 全量分层（6 个编号目录）+ 同步全部引用（含 ~100 处代码注释） | diff 大（96 文件 / 约 200 处）；但换来"路径即层级"的自解释结构 |
| D 顺带删 | 判断信息已被 `AGENTS.md §1/§2` 与 `计划.md` 覆盖的直接 `git rm` | 最精简；但会丢掉 spike 时代的沿革记录（这些记录的价值在于解释"为什么是现在这样"） |

## 选择

**C 彻底分层 + 分类处置过期件 + 全修死链**（用户 2026-09-15 拍板）。

- 结构：`docs/README.md`（唯一索引，留在根）+ `00-入口/`、`10-契约/`（含 `specs/`）、`20-验收/`、`30-决策/`（原 `decisions/` 改名）、`40-模块/`、`90-历史/`。
- 过期件分类处置：`01-总览.md`、`02-架构.md` **内容不重写**、移入 `90-历史/` 并加过期横幅（保留沿革 + 阻断误读）；原 spec 留 `10-契约/specs/` 加历史横幅（标注其路径指向 fork 前旧仓库）；`40-模块/README.md` 重写为覆盖全模块的真索引；根 `README.md` 重写为真项目入口。
- 引用同步：`git mv` 保历史 + 单趟替换（96 文件、约 200 处），改完立刻全量回归。

理由：分层的唯一价值是"一次 grep 就能定位、且不必逐篇判断时效"；留 5 篇在根等于让后来的人继续面对混杂根目录。代价是纯粹的机械替换，且有 18 套件托底——风险与收益成比例。

## 后果

**得到的**：
- `docs/` 自解释：看目录就知道该读哪层；`docs/README.md` 是唯一索引；权威表按主题列明了"谁是权威 / 谁是历史"。
- 死链清零（仓库自有 md 零死链；唯一剩余 1 条在 `sidecar/.venv-win` 第三方包内，不动）。
- 代码注释里的文档路径与磁盘一致，决策文件改名后铁律 5、`AGENTS.md §1/§2` 同批更新。
- 数字按实测回写：测试基线 `236` → **288**（18 套件实测汇总；两套汇总格式 `TOTAL: N passed` 与 `结果：PASS N`）；`AGENTS.md` 的提交数/文件数改为"实时值看命令"，不再写死。

**代价与风险**：
- diff 大（116 文件：20 重命名 / 87 修改 / 7 删除 / 2 新增），按 3 个原子 commit 拆分提交便于逐段核对
- `decisions/` → `30-决策/` 是**路径变更**，任何外部引用（本仓之外的笔记/会话）需自行更新。
- 视觉回归无自动断言——但本轮不碰任何 `.gd` 逻辑，只改注释文本，全量测试是充分托底。

**有意未做**：
- 不重写 `90-历史/` 正文，只加横幅——它们的价值是沿革记录，改写等于伪造历史。
- 不动 `research/lmcc/**`（原始调研资产，改它等于污染记录）；其内部引用的产物路径（`data/eNN_*.json` 等）是调研计划口径，不属本轮范围。
- 不把死链检查脚本落库（本轮一次性跑，避免为一次性需求新增维护面）。
- 不补 CHANGELOG / 不统一版本号（W4 独立债）。

**意外发现（本轮未动，单列）**：
1. 工作区**全仓 CRLF**，与 `.gitattributes` 的 `*.gd/*.sh/*.py text eol=lf` 不符（对照组：未修改的 `world_state_core.gd` 498/498 行、`run_tests.sh` 145/145 行都是 CRLF）。属既有状况——本轮编辑保持了原样（`git diff --numstat` 每文件恰好 2/2 行，无行尾翻动）。要不要归一化另议。
2. **`assets.yaml` 不是死链**：`assets/assets.yaml` 真实存在（28 条 `assetId`，资产台账主索引），文档里那 6 处只是省略了目录前缀——已补全为 `assets/assets.yaml`，**没有**按最初的误判改成 `concepts.yaml`。
3. **中文替换串的编码坑**（本轮踩中并修复）：`perl -CSD -i -pe` 配合命令行上的中文字面量会把中文**双重编码**（`决策` → `å³ç`）。安全做法：脚本内 `use utf8` + 显式 `:encoding(UTF-8)`，或**不加 `-C` 的字节模式**（读写都是原始 UTF-8 字节）。改完必须用能正确处理 UTF-8 的方式复读校验，别信被 `cut -c` 截断过的终端回显。
