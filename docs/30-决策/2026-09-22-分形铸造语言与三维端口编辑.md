# 2026-09-22 · 分形铸造语言与三维端口编辑（Agent Lab 补完轮）

## 背景

可执行 Agent 沙盒（2026-09-22 首版）交付时留了三条实现边界：三维视图没有端口直接拖线、节点参数是裸 JSON 输入框、第一课视频仍是旧界面。同时三维整机观感粗糙：节点是素色扁盒按 `idx % 7` 机械网格排布，连线是无向直角 L 段。用户裁定：以最新的文件为准清理过期文档；美观度要修；基础引擎要更鲁棒更美观；**架构与形状设计完全参考 Fractal Foundry**（[官方站](https://fractalfoundrygame.com/)、Steam app 4289960），并认真调研工厂/编程类游戏的技术实践后落地。

调研结论（2026-09-22）：

- **Fractal Foundry**（Tiny Root Studio，未发售）：立方体基元起步；工厂可作为可复用模块嵌进更大的工厂；工厂可自嵌形成真递归；循环/条件/变量即逻辑层；无资源压力的纯沙盒；视觉是自相似的分形体素结构（雪花、金字塔）。
- **工厂游戏工程实践**：Factorio FFF-276——传送带物品用整数像素进度而非物理，间距必须整除格宽（把表现层的量整格化，保证确定性与可读）；shapez——建筑由统一注册表数据驱动（MetaBuilding/prototypes），模拟与渲染分层；Factorio 渲染对象用数值 ID、可变属性、与模拟解耦。共同点：**确定性模拟单源、表现层只读数据、词汇表收敛**。

## 备选

1. 三维整机继续手排特例坐标，只把颜色调好——改动最小，但布局仍读不出控制流方向，且每个新程序都要手排。
2. 引入通用图布局库/力导向算法——表达不了"控制流定列、纯数据上带"的教学语义，且引入依赖。
3. 三维编辑只做"点开节点跳二维编辑器"（现状）——端口拖线停留在二维，三维永远只是展示。

## 选择

**形状语言（Fractal Foundry 式）**：新增共享构建器 `game/scripts/lessons/machine_view.gd`，一处代码服务场景、测试、视频导出三处：

- **确定性分层布局**：控制流自入口广度优先定列（入口最左、沿连线向右，循环回边自然拉出长回程线）；纯数据节点排同列上带，超四行折副列；所有摆位落 0.25 m 网格；布局不读节点 label（同 Factorio 整数像素的精神：表现层的量整格化、可复现）。
- **分类造型 + 自相似提示**：`call` 节点画成三层叠板向右上收窄（"模块里还有模块"）；工具节点按 `world.*`/`fs.*` 分色小方块；工具集合是带字段插槽的低板；控制类节点顶 0.25 m 色帽（模型紫、分派橙、消息蓝……取自资产色板）。
- **端口与走线**：每节点左右两面出橙（控制）/蓝（数据）端口块，正交走线升到统一线高，末端加方向箭头——颜色之外再叠箭头区分（交互方案契约要求）。

**三维端口直接拖线**（`agent_lab.gd`）：按住端口拖出半透明预览线，落在另一端口连线、从已连输入口拖到空白断线；控制/数据类型不匹配即时拒绝；单驱动替换（该输入口旧线、该控制出口旧线先移除）；成功即保存到后端（草稿可带校验错误，与二维编辑器口径一致），失败自动回滚重载。

**参数编辑结构化**（`module_editor.gd`）：const/input/get/tool/message/集合类节点给具名字段（工具绑定用下拉，目录来自后端 `/program` 返回的 `tools` 列表——真源仍是 `module_compiler.TOOLS`）；未覆盖键回退 JSON 行。端口表在 Godot 侧收敛为 `machine_view.PORTS` 单一真源，二维编辑器针脚显示复用之。

**顺手修复的真 bug**：`extract_selection` 把返回值边写死 `"result.value"`，而返回节点实际是 `fresh("result")` 随机 id，封装后模块必编译失败；改为 `return_id + ".value"`，由既有回归暴露、修复后复绿。

**视频更新口径**：旁白与秒位保持第一课 v9 不动；`render_lesson.py` 引入从**当前真实程序**导出的整机几何（新导出器 `export_agent_lab_gltf.gd`，读 `game/agent-lab/program.json`，几何与场景同源），摆在概念件右侧；`representation` 镜从概念件横移到整机，`scope` 镜聚焦工具绑定列——旁白讲"可视化表示/工具与权限"时画面即真实程序，不再与"未更新为新界面"的边界冲突。

## 后果

- 三维整机从"展台摆件"变成可编辑视图：教学上"方块=软件模块的可视化表示"有了逐端口对应的实物。
- `machine_view.gd` 成为第三个几何真源消费方（场景/测试/glTF），以后改形状只动一处；但 Python 侧 `PORTS` 与 GDScript 侧 `machine_view.PORTS` 仍是两份镜像（与改动前同构，靠编译器校验兜底）。
- 三维拖线保存即时生效（无草稿缓冲），与二维编辑器"显式保存"并存：三维适合快改，二维仍是精编入口。
- 第一课视频的几何来源从"五件展示模块"扩为"五件 + 可执行整机"，五件保留作概念特写；成片需重渲染重合成（本轮完成）。
- 仍未做：旧工坊 26 件迁移为程序节点（产品决定保持工坊为资产浏览）；三维视图不显示模块内部（进模块仍走二维图）。
