> 这篇讲：别人用过哪些手段把方块世界做出辨识度，哪些便宜哪些贵，以及本项目采用哪几条。

## 为什么这件事是生死线

方块是世界游戏里最饱和的形态。玩家看到"方块地形 + 第一人称 + 绿草蓝天"会在三秒内给出结论："这是 MC"。技术能跑通不等于产品成立。

所以本项目的验收口径不是"技术上线框能不能跑"，而是：**一个没听过这个项目的人看三秒，会不会说这是 MC。**

## 六条手段，按性价比排序

### ① 镜头语言 —— 最便宜，最有效

MC 的签名之一是**固定第一人称、1.8 米眼高、FOV 70、无景深**。换成**正交（orthographic）等距视角 + 轻微移轴虚化**，画面立刻读作"微缩沙盘"而不是"我在里面生存"。

零资产成本，纯参数。参照：《Townscaper》《Islanders》《Bad North》都用等距正交镜头，没人会把它们误认成 MC。

### ② 限定调色板 —— 便宜

MC 的默认配色是一个很具体的配方：**饱和绿草 + 蓝天 + 土黄**。避开它就行。

做法：16–64 色的固定调色板，冷色单色系打底 + **一个暖色强调**。这也符合"简约线条"的诉求。参照做法见 [voxel-art patterns 的 palette-first](https://github.com/omer-metin/skills-for-antigravity/blob/main/skills/voxel-art/references/patterns.md)：每个材质至少要有阴影/中间/高光三个色调变体。

### ③ 去像素贴图 + 描边 —— 便宜

MC 的另一个签名：**16×16 像素贴图、无 PBR、硬边 AO**。换成纯色 + 平滑法线 + PBR 粗糙度变化，同样的方块几何观感立刻不同。再叠一层**反向法线描边**，就是"线条非常明晰"。

这三条（镜头、配色、描边）合起来几乎不花钱，却已经能拉开大部分距离。

### ④ 平滑法线 / 软方块 —— 中等

保留方块网格但把法线做圆滑，或直接用 marching cubes，让地形读作连续曲面。参照《No Man's Sky》《Astroneer》——它们的体素地形一点都不"方块"。

注意：`voxel-art patterns` 把"用 marching cubes 做方块风"列为反模式（会毁掉块感），所以这条与③互斥——**要么方块味，要么曲面味，不要混**。

### ⑤ 让体素小于视觉单位 —— 贵

《Teardown》的[体素约 10 厘米](https://teardown.fandom.com/wiki/Voxels)，世界读作连续物质，"方块"不再是视觉单位。MC 的 1 米方块既是物理单位也是视觉单位，这是它最强的签名。

代价：体素数量爆炸，需要光线步进或高效网格化，而且**建造手感会变碎**——对建造类玩法是负分。

### ⑥ 隐藏网格 —— 最贵

《Townscaper》的做法：在六边形里生成三角形、去掉边形成四边形，再用 Wave Function Collapse 拼装，最终**完全看不出格子**，呈现弯曲有机的欧洲老城（[Domestika 访谈](https://www.domestika.org/en/blog/4218-el-proceso-creativo-detras-del-videojuego-townscaper)）。

效果最好，但它是一套完整的几何化算法，属于"建造玩具"路线，不是沙盒生存路线。

## 本项目的选择

**采用 ①②③，放弃 ④⑤⑥。**

| 手段 | 决定 | 理由 |
|---|---|---|
| ① 正交等距 + 微缩 | **采用** | 零成本，收益最大 |
| ② 限定调色板 | **采用** | 零成本，且服务"简约线条" |
| ③ 纯色 + 描边 | **采用** | 零成本，是"线条明晰"的落点 |
| ④ 平滑法线 | 放弃 | 与③的方块线条感冲突 |
| ⑤ 小体素 | 放弃 | 建造手感会碎，且体素量爆炸 |
| ⑥ 隐藏网格 | 放弃 | 工程量大，且我们要的是建造沙盒 |

**保留 1 米体素作为建造粒度**（保住建造手感），但视觉上靠描边与配色做出身份——不靠几何形状。

## 一个重要的发现

翻回本项目的历史可以看到：**第七版（浮空板块 + 描边 + 高饱和 + 微微俯视）的美术方向其实已经对了**——它已经具备①③的雏形，观感与方块世界有明显区分。当时的错误是**几何形状选了六棱柱**，而不是美术方向错了。

现在几何换回方块（为了复用 `godot_voxel` 的区块与流式加载），**那套美术方向可以直接搬过来**，不需要重新摸索。

## 高科技方向（2026-09-13 落地）

用户在看完成品后定调：**要高科技 taste**。于是把"自然地貌"整体换掉，配方如下。

### 配方

| 要素 | 做法 |
|---|---|
| 基底 | 深色冷调（#0E1420 → #3D4C63 四档），结构方块带 0.28 金属度，读作"加工过的材料"而非泥土 |
| 地貌 | 台地 + 分层崖面。地表不是草地，是**甲板** |
| 纹样 | 每 8 格嵌一道**发光电路线**，在地面上织出网格 |
| 焦点 | 机器平台用暖橙（#E08A3C），四角信标塔顶青色发光核心（#4FE3F5） |
| 光照 | 主光冷白塑形 + **一盏冷色补光**（不投影）把暗面从死黑里拉起来 |
| 后处理 | AgX + Bloom（阈值 1.0、强度 0.55）+ 冷色距离雾 |

### 一次明确的过头

第一版把电路线自发光调到 **1.3**、Bloom 强度 **1.10**，结果整片地形烧成霓虹灯管，地形本身反而看不见了——画面读作"电路板"，不是一个"地方"。

**高科技的正确配比是：绝大多数面是哑光暗面，只有少量精确的亮线。** 把电路线压到 **0.45**、核心压到 **1.5**、Bloom 降到 0.55 之后才对。

这条值得记住：**发光不是越多越"高科技"，越少越精确才像。**

## 方向修正：明亮 + Q 弹 + 小粒子（2026-09-13 定稿）

用户看完成品后的原话：**"整体应该是明亮的，而且比较 Q 弹，粒子应该偏小一点，补充一点粒子特效，而不是直淋淋的光源"**。

上一版做成深色夜景霓虹，方向错了。修正如下。

### 改了什么

| 项 | 深色版 | 明亮版 |
|---|---|---|
| 系度 | 近黑夜空 | 亮蓝天穹 + 浅蓝灰地面 |
| 底色 | `#0E1420` → `#3D4C63` | `#3A4658` → `#A9B9CD` |
| 发光 | 自发光 1.5，Bloom 0.55，醒目刺眼 | 自发光 1.10/0.55，Bloom 0.45/0.30，只是"表面发亮" |
| 光的表现 | 发光方块本体就是光源 | **小颗粒粒子**（直径 0.22 ≈ 2 像素，每座信标 64 颗）缓慢上浮淡出 |
| 补光 | 冷蓝 0.40 | 暖白 0.55，亮场景的暗面该是暖灰不是死黑 |

### 两次过头，两次教训

1. **深色版发光拉满** → 整片烧成霓虹灯管，地形反而看不见。教训：发光不是越多越高科技。
2. **明亮版第一稿** → 底色 `#D9E2EC` 接近白，叠上 1.55 环境光，整幅洗成白泡沫模型，标准差只有 21.3。教训：**底色要"亮但有颜色"，不能接近白**；青色线与白色辉光在近白底上会全糊在一起。

### 粒子尺寸的坑

正交相机（`size = 74`，1280×720）下 **1 世界单位 ≈ 10 像素**。第一版颗粒给 0.085，只有 0.8 像素——**等于看不见**。

教训：**"小"不等于"不可见"**。2 像素是这类点缀粒子的下限。

### 相机路线：已裁决（2026-09-13）

用户裁决：**第三人称，相机自由换。参考《围攻》（Besiege）。**

这条把上表 ① 的"正交等距为主"改掉了：正交等距**降为预设位之一**，不再是主视角。理由是我们的产品本来就是"看一台机器干活"——《围攻》里玩家造一台机器，然后第三人称绕着它看它跑，这正是我们 mini codex 与机械臂的处境。

| 项 | 裁决 |
|---|---|
| 主视角 | 第三人称轨道相机：绕主体旋转、平移、缩放，可跟随主体 |
| 自由换 | 相机是**玩家的工具**：随时切预设位、随时切自由视角、随时切跟随 |
| 预设位 | 正交等距（结构可读，讲机制时用）、正视、俯视、特写、远景（存在感用）。预设只是存下来的机位姿态，不是限制 |
| 时间控制 | 播放 / 暂停 / 慢放 / 加速，与相机并列为一等公民（《围攻》式） |
| 微课取景 | 分镜轨记录**自由相机的关键帧**，不限于预设位 |
| 景深与暗角 | 后加项，但接口现在留出（参考图的开关形态） |

**引用《围攻》的边界**：借它的**相机与时间控制**，也借它的**物理标准**——用户已裁决物理只要"勉强好用、像 MC 与围攻"即可，不追求精确、不追求可复现，所以《围攻》的物理不可复现这件事不再是问题。唯一的例外仍然是**慢放**：不得靠放大物理步长实现（那会让东西穿透、堆叠炸开，画面变糙，官方论坛有这个实测现象），只能靠取帧策略。

### 结构项 vs 后加项

用户此前裁决过「**画质与光影属后加项，结构未定前不投入**」。按这条把参考图的要素分两堆：

**属于结构、现在就得保住（否则以后做不到）**

| 项 | 为什么是结构 |
|---|---|
| 地形高差与尺度 | 世界生成参数与规模决定，改晚了要重做地形 |
| 区块流式加载 + LOD | 没有它就做不出"远山分三层退远" |
| 天空与大气系统 | 渐变天 + 空气透视是氛围的地基，不是后处理能补的 |
| 单光源与时间 | 光照模型与昼夜决定色温基调 |
| 水面与瀑布 | 水的两态是地形生成的一部分 |
| 相机系统 | **第三人称轨道相机 + 自由换视角 + 时间控制**（见下节裁决）。这条是体验的骨架，不是后加项 |

**属于后加项（按用户裁决先不投入）**：具体调色与指标、粒子细节、Bloom 强度、材质粗糙度、暗角的曲线。

### 我们的 taste 空间在哪

### 方块的"本体设计"：倒角 + 砖 + 花纹（2026-09-16 第二轮；倒角参数 2026-09-17 裁定）

用户看完成品后的第二条反馈：**"它的方块依然是方块，但并不是一个正方体，它旁边有倒角和
花纹设计"**。这是对的 —— 第一轮只做了配色、地形与光照，**方块本体还是一颗平色立方体**，
而这恰恰是《Zoy》石砌的精髓所在。回到参考图放大看，读出来的设计语汇是四条：

| 语汇 | 做法 | 落在哪 |
|---|---|---|
| ① 倒角 | 12 条棱 + 8 个角各切一刀（**直切 45°、直角边 0.05 m**，2026-09-17 裁定统一；向内切、不改占格），相邻方块之间自然形成凹缝 | `sandbox_block.gdshader` 管颜色，**几何在 `sandbox_block.gd` 的 `block_mesh()`** |
| ② 顺砖砌法 | 逐行错半砖、再按方块坐标整体错一次（两向都错开，竖缝才不连成直线） | 同上，砖格尺寸按面走 |
| ③ 逐砖斑驳 | 同族色按坐标哈希散深浅 ±15% + 低频风化斑 + 逐砖"上亮下暗"的倒角 | 同上 |

**分工**：地面上的方块是"一方块一块石板"（砖格与方块重合，**砖缝就是倒角几何本身**）；
墙面是"一个方块两皮砖 + 砖上沿一道受光亮棱"。这条分工是被实测逼出来的：给平地面再画

砌体在墙上。

### 四条本轮教训（都花了好几轮截图才找到）

1. **"用法线判断这块面平不平"是不可靠的**。着色器里用 `max(|NORMAL|)` 去挑平面、
   想在倒角棱面上关掉图案 —— 实测这个值在网格器插值后的法线上几乎恒为 0，
   于是整段砌体图案与花纹被 `mix(plain, albedo, face_flat)` 全吃掉。表现是"砖缝、
   斑驳、花纹全都没有，只剩倒角几何 + 调色板色"，看起来就是一块瓷砖地 —— **症状
   像是"砖没画出来"，真因却是"画了又被掩码吃掉"**。定位方法：把掩码强制设为 1
   渲一张，图案立刻满屏。
2. **花纹的尺寸必须用世界单位（米）写**。第一版写成"占砖格的比例"（0.026），
   在 34 m 机位下 1 m ≈ 37 px，那根线只有 0.5 px，整片花纹被抗锯齿滤没。
   现在砖格、砖缝、花纹线宽全是米制，且互相之间的尺度关系明确（倒角 0.05 / 砖缝 0.030 /
   花纹线 0.10；倒角是几何，后两者是材质层表面绘制）。**点比线抗缩放**：远景里先活下来的是芽纹叶尖那两个实心点。
3. **`VoxelBlockyModelMesh` 不出任何碰撞体**。要走自定义方块几何，就得放弃体素地形
   自带的碰撞：同一套 `VoxelTerrain` 配置下，模型换成 `VoxelBlockyModelCube` 射线能
   命中甲板，换成 `VoxelBlockyModelMesh` 则 `collision_aabbs` 与
   `set_mesh_collision_enabled` 怎么配都是 0 命中。现在的做法是
   `sandbox_diorama.add_deck_collision()`：按形状函数（`is_land`）铺一层 2 m 的静态
   盒子栅格当甲板。副作用是好的 —— 代理是**同步**建好的，不像体素碰撞异步流式到位，
   拖拽落定不再有"头几帧没有地面"的窗口。
4. **倒角宽度是"两级缝"的比值问题**。倒角 0.075（旧值）时块缝(0.15 m)比砖缝(0.024 m，旧值)宽 6 倍，
   尺度差一大，表面就读成"瓷砖 + 勾缝"；倒角收细到现行 0.05 m（2026-09-17 裁定值）之后，
   两级才像同一种砌体。

`run_island_tests.gd` 的 **T9（甲板碰撞射线）**：上面第 3 条一旦配错，甲板就没有碰撞，

这类"删掉一整块物理能力却全绿"的改动，只能靠射线单独钉住。

## 第三轮修正：坐标空间与甲板轮廓（2026-09-16 · A1，依据执行计划）

前两轮把观感做出来了，但**表面图案其实是错的**——从单张截图完全看不出来。
本轮只修正确性，不动配方取向。完整证据与逐条验证见
[`20-验收/2026-09-16-美术改造-A0A1.md`](../20-验收/2026-09-16-美术改造-A0A1.md)。

### 1. 砖纹/花纹的坐标原来是**视空间**的

`sandbox_block.gdshader` 在 `fragment()` 里写 `MODEL_MATRIX * vec4(VERTEX, 1.0)` 求世界坐标。
但 Godot spatial shader 的 **fragment 阶段 VERTEX 与 NORMAL 都是视空间**，`MODEL_MATRIX` 是
"模型→世界"——两者相乘得到的既不是世界也不是视空间，而是**跟着相机转**的坐标。
实测复现方式：把 `fract(wp.y)` 直接画成灰度渲一张。**平坦岛顶在世界空间里 y 是常量、该整片同灰**，
改前是沿画面高低变化的条带（条带方向就是相机右向），改后才是整片同灰 + 崖壁按世界高度分层。

后果是砖缝、逐砖斑驳、风化与花纹**全焊在相机上**：环绕时在方块表面游动，"这块砖长得不一样"
这件事其实取决于镜头位置。`NORMAL.y` 判"哪块面算顶面"同理随俯角翻转（默认全景俯角下恰好侥幸正确）。

**修法（现行口径）**：世界位置与世界法线在 `vertex()` 里算好，经 `varying vec3 v_world_pos /
v_world_nrm` 传到 fragment。**任何世界量都走这条路**。回归锁
`tests/sandbox/run_shader_space_tests.gd` T1/T2（修复前实测会红）。

### 2. 草的"向上"也混错了空间（**该 shader 已于 2026-09-16 删除，本节仅存档**）

> 草改成顶层方块的表面之后，`sandbox_grass.gdshader` 整份被删（见本文 §5）。
> 这条"视空间法线不能与世界向上常量混合"的坑本身仍然有效，记在 `AGENTS.md` 已知坑位 7。

`sandbox_grass.gdshader` 把 fragment 法线混向常量 `(0,1,0)` 以让薄叶片读作受光地毯
（意图保留），但那在视空间里是**相机的上** —— 草的受光跟着镜头转。
修法：`up_in_view = normalize((VIEW_MATRIX * vec4(0,1,0,0)).xyz)` 再混。
验证是同机位只换 shader 的对照：斜视机位（pitch 0.50）有可见变化、差分**只落在草环上**，
而把镜头放平（pitch 0.02，视空间上＝世界上）时两版几乎逐像素相同。

> 教训（已进 `AGENTS.md` 已知坑位）：这类"源码契约"检查**必须先剥注释**。
> 第一版 T3 在修复前的 shader 上假绿过——fragment 里那句解释性注释里出现了 `VIEW_MATRIX`。

### 3. 甲板碰撞代理的轮廓误差被收进半块以内

甲板代理是"按格中心 `is_land()` 铺盒子"，轮廓误差就是格距的量级。按 L4 半径实测：

| `DECK_CELL_M` | 盒子数 | 岛内最大缺口 | 岛外最大溢出 |
|---|---|---|---|
| 2.0（原值） | 175 | 0.95 m | **1.10 m** |
| **0.5（现行）** | 2665 | 0.20 m | 0.16 m |

原值的 1.10 m 溢出＝离崖口两格多还有一层**看不见的地板**（拖拽落定会停在空气上）。
收进 0.5 m（= 一个标准方块）后误差不超过半块。多点射线的回归锁在
`tests/sandbox/run_ground_tests.gd` T1（16 方向 × 0.1 m，1634 点，不止打中心）。

### 4. 生成台摆位：同向、落格、不穿模（2026-09-16 用户口径）

用户口径：**资产都是方块组成的、方向一致，所以每件的位置应当由 (x,y,z) 唯一确定，且互不穿模。**
现行做法（`sandbox.gd` 的 `_add_workstation` / `_pack_slots`）：

- **占格按实测可见包围盒**，不按声明 footprint —— 实测 21/28 件的几何超出 footprint
  （`conc_loop_gallery` 深 +2.13 m 最甚），按 footprint 排必穿模。
  占格 = `ceil((实测 + 0.25) / 0.5)` 个标准方块，件居格中 ⇒ 相邻件可见体之间必留 ≥0.25 m。
- **一律 `yaw = 0`**：不再把深比宽长的件转 90°。同向是"坐标唯一确定"的前提。
- **行宽按台面形状算**（L4 半径推该行可用半宽），行按占格进深降序做 shelf packing。
- **载体碰撞体 = 实测可见范围**（不再 `clampf` 截短）；基座就是占格 —— 画面上的底片即"这件占了哪几格"。
- **顺序铁律：先摆位、再 `add_child`**（`AnimatableBody3D` 的坑，见 `AGENTS.md` 已知坑位 9）。

回归锁：`tests/sandbox/run_ground_tests.gd` T3/T4/T5/T6。

**外延落格（2026-09-17 用户裁定，取代「中心 + 尺寸」口径）**：落格口径从部件的**中心与尺寸**升格为
**部件盒外延六面全部落 0.25 m 格点**（"占满整格"；中心允许 0.125 m 奇半格偏移）。28 件已全部按此重排
（不少件改了出厂几何——带宽、环砖、屏比例等，清单见验收报告）；占格基座垫高到 0.25 m（`PLINTH_H`），
摆位排序补成全序（进深降序、并列按 id 升序）保证逐字节确定。回归锁升格为 `run_ground_tests.gd`
**T7**（T3/T4/T5/T6 照旧）；数学口径与对账见
[`../20-验收/2026-09-17-外延落格与暖草色.md`](../20-验收/2026-09-17-外延落格与暖草色.md)。

### 5. 草改成顶层方块的表面（2026-09-16 用户口径）

用户口径：**不要把草做成长那么高的东西；把方块最上面那一层渲染成草的样子，总体形状还是正方体。**
于是删掉了整套草叶几何（`sandbox_grass.gdshader` + `sandbox_flora.add_grass` 里的约 1.9 万株 MultiMesh），
草改由 `sandbox_block.gdshader` 的 **pattern_kind 3（草皮顶块）** 表达：

| 面 | 画什么 |
|---|---|
| 顶面（含顶棱倒角，`abs(nrm.y) > 0.5`） | 成片草色：两级**平滑**噪声定深浅（约 2 m 成片 + 约 0.3 m 细斑），再乘逐块微差 |
| 侧面 | 土壤色 + 顶部 `grass_side_band = 0.20 m` 的**草皮断面**（界线带锯齿）——崖口因此读作"草盖顶的土崖" |
| 几何 | **一点不加**。方块仍是正方体，岛形与剪影不变 |

`pattern_kind 3` 只挂在**顶层方块**上：`sandbox_island._top_type_at` 只在 `d == 0` 给 T_TURF / T_DRY，
下面全是地层色；用色与"草长在哪"走同一个判定（`is_turf_top(rr, x, z)`），两处不会漂。

三条本轮教训：

1. **成片要用平滑噪声，不能用 `floor()` 的硬格子**。第一版拿硬格子做"成团"，出来的是一块块
   高对比方斑，在画面上读作**烧焦的印记**，不是草。
2. **顶面不能给暖金/沙色**。第二版沿用了被删掉的草叶 shader 的暖金梢色 `#FFA529`，整圈读作**沙地**。
   草得有自己的暖色 —— 现行取**芥末琥珀**（2026-09-17 定稿，见下）。
3. **与"避开《我的世界》配方"的张力（2026-09-17 已了结）**：本文件开头 §② 说得很明确 ——
   "饱和绿草 + 蓝天 + 土黄"是 MC 的签名配色，要避开；而顶面是草、天空是饱和蓝、铺装是暖砂三条同时在场。
   缓解之处在于本项目其余身份（浮空岛、砖砌镶边、珊瑚橙机器、微缩箱庭机位）与它分开。

**草色现行口径（2026-09-17 定稿）**：**芥末琥珀** `grass_deep #352509` / `grass_tip #E8B23E`——
两处 uniform 即全部改动，不动几何、不动结构。两轮迭代：第一轮 `#FFA529` 被否——整圈读作
**麦田/沙漠**，草/铺装/沙三层退化成纯明度对比（教训 2 对暖金的判读在暖色上重演了一次）；第二轮定稿
芥末琥珀——保持暖调、更像干草，三层分层靠铺装边线救场（调色时别再把铺装也往暖里推）。结论：
草要暖可以，但不能是饱和橙，要"暗一档的干草"。

> 沿革：定稿前顶面一度取低饱和橄榄绿 `#33431B → #6F8F45`（2026-09-16 的过渡稿），2026-09-17 裁定改暖后作废。

对照证据：`game/shots/art-upgrade/A4/`（v1/v2 各三机位）。

回归锁：`run_island_tests` **T10**（草皮方块只出现在 `wy == TOP_WY`、材质走草皮档 3）与
**T8**（场景里**没有**草叶几何 —— 草要是又变回几何，这条会红）。

### 6. 全场景方块合规（2026-09-16 第二轮，用户口径「所有资产都是方块组成，方向也一样」）

草改成顶层方块表面之后，用户追问"为什么还有斜着的东西"，于是把口径推广到**整个沙盒场景**
（不只那一圈草）。两轮下来清掉的东西：

| 原来 | 现在 |
|---|---|
| 南侧工区整棵子树 yaw ±33.2°（`PLAYER_YAW`/`HELP_YAW` 是"转朝镜头"的任意角） | yaw **0** |
| 播放器 / 求助屏的幕布是 `PlaneMesh`（默认 `FACE_Y` = **躺着**，还从边框里穿出来） | 竖直**方块**面板（两个幕布都改） |
| 树 = 圆柱树干 + 4 个压扁的球冠，每棵随机偏航；石 = 球 | **方块树**（树干 + 十字冠）/ **方块石**，朝向只取 0/90/180/270 |
| 闸门岔路地条 −28.6°、门体 −18°/78° | 岔路收成直角、门体 **0°/90°** |
| 机械臂肩 −32° / 腕 58° | 肩 **90°** / 腕 **0°**（整条臂水平指向柜格） |
| 工具带四把头 = Prism/Cylinder/Torus（还被测试钉死） | 四把全方块，靠**块数**区分：读=1 / 写=2 / 跑=3 / 搜=4 |
| 计划板箭头 / 播放三角 = PrismMesh | 方块 |

**现行口径（写进回归锁）**：`tests/sandbox/run_block_conformance_tests.gd` 从场景根扫下来，
要求 **每个可见几何都是 `BoxMesh`、每个节点的旋转都是 90° 的整数倍**。
（表面细节的几何手段只有倒角一种、其余一律纯盒；第二波教学资产 rollout 推广 0.05 m 倒角时，
这条「全 BoxMesh」契约需同步调整——见 ADR「后果」节。）

**另外两条裁定（2026-09-17）**：

- **落格**取更严的"**外延也落格**"读法——部件盒外延六面全部落 0.25 m 格点，28 件已全部重排
  （见上文 §4，回归锁 T7）。
- **「主体包络内的表面细节」**：裸露表面统一**直切 45° × 0.05 m 倒角**（向内切、不改占格；
  砖缝/花纹留材质层、不涉几何），自然装饰全删——见
  [`../30-决策/2026-09-16-教学资产表面细节尺度.md`](../30-决策/2026-09-16-教学资产表面细节尺度.md)。
