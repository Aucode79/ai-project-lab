# 交互方案 · 学员怎么用这个东西

> 2026-09-13 · 设计文档。本文定"学员的手在做什么、眼睛看什么、系统怎么回应"。
> 上游：[`specs/2026-09-13-sandbox-as-studio-design.md`](specs/2026-09-13-sandbox-as-studio-design.md)、[`mini-codex.md`](mini-codex.md)、[`方块体系.md`](方块体系.md)。
> 外部依据：`research/lmcc/raw/G-教育编程游戏交互.md`（12 个教育编程产品 / 9 维度）、`research/lmcc/raw/E-编程游戏.md`（编程游戏设计）。

## 一、一关的全循环

demo 是一条五关的线性关卡链（spec §9.1.1），每关的动作序列一样：

| # | 学员做什么 | 手上动作 | 世界怎么回应 |
|---|---|---|---|
| 1 | 看这一关的片子 | 走到播放器；空格暂停，`,` / `.` 前后十秒 | 成片镜位固定；能自由切机位的是沙盒演示，不是成片 |
| 2 | 把本关组件装上去 | **长按**抓起方块，看虚影吸附到格点，松手落位；连线从端口长按拖到端口；**点按**任一物件可占满全屏看它的代码或面板 | 拼装合法与否**即时**反馈（虚影变红即不合法，不等编译） |
| 3 | 跑一遍 | 按**单一运行键**（空格） | 整条流程跑起来，相机跟着 codex 走，组件依次亮 |
| 4 | 改一个参数 | 拖旋钮 | 结果立刻变；看的是"与上一版的差异"，不是分数 |
| 5 | 交评分 | 点「评价」 | codex 出**五维诊断语句**（§七） |
| 6 | 进下一关 | 走到下一关的工位 | 本关组件留在装置上，下一关接着用 |

第 3 到 5 步就是教学法三级：**跑一遍是观摹，拧旋钮是接管，自己装是手写**。

## 二、手在做什么

两种手势分得干净：**长按是搬，点按是开**。

| 手势 | 结果 |
|---|---|
| **长按** | 抓住这个物件进入拖拽：本体跟手抬起，同时出现**虚影**标出落点 |
| **点按** | **打开**它——看它生成的代码，或打开它的面板 |
| 打开后的视图 | **占满全屏**做进一步交互；关掉立刻回到世界 |
| 鼠标移动 | 控制**方向**（视角朝向） |
| 右键拖动 | 控制**摄像机位置**（平移） |
| 滚轮 | 缩放 |
| 空格 | **单一运行键**：跑 / 停 |
| `,` `.` | 前后十秒（看视频时）；单步前后（跑演示时） |
| `Tab` | 切预设位（iso / front / top / close / vista） |

**为什么拖拽要长按**：点按的后果是"占满全屏"这么重的动作，拖拽就不能也挂在短按上，否则一动就误开。长按给了一次确认的机会。

沙盒的存档、读档、导出按钮固定在工位上，点按即可执行，长按不会把按钮搬走。相机输入由交互总装统一处理一次；长按触发与松手落在同一物理帧时也会完成释放。

**虚影 = 落点预测**（用户定义）：松开手之后它会掉到哪里、以什么姿态停住，虚影就画在那里。

| 项 | 口径 |
|---|---|
| 虚影是什么 | 松手瞬间的**物理落点与静止姿态**，不是网格吸附标记 |
| 怎么算 | **必须用同一套物理前推**（快进若干步算出来），不能另写一套启发式——否则虚影会撒谎；撒谎几次之后学员就不再看它了，整个拖拽的手感也就没了 |
| 实际物体 | 跟手抬起走，有重量感、会被别的东西挡住 |
| 合法性 | 是**另一件事**：端口类型匹配、越界、重叠这些**编译期校验**的结果用颜色标（绿 / 红），与"落在哪"分开表达 |
| 建造即投放 | 可以从高处往下丢，它会掉下去停住——建造的手感因此是物理的 |

**投放怎么跟状态层接上**：落定那一刻**上报一次**，状态层接管该格点；落定之后物理不再移动它（spec §7.1 的单向上报）。"可以往下丢"与"判定不读物理"两条能同时成立，靠的就是这一次上报。

**来源**：建造类游戏的通行做法（《围攻》《废品机械师》《我的世界》），并由用户指定；单一运行键与展开菜单的部分来自 Swift Playgrounds（`G-教育编程游戏交互.md`）。

**全屏视图是"界面上不放东西"的唯一例外**，边界要写清：它只在**打开某个东西**时出现（看代码、看面板），**不常驻**，关掉立刻回到世界。它是"打开一个物件"的结果，不是一块常驻 HUD。

**旋钮不用键盘输数字**，拖拽微调。**代码不用打字**——三级默认看拼装生成的 Python，那正是点按打开后的全屏视图。

## 三、眼睛看什么

| 区域 | 内容 |
|---|---|
| 主区 | 世界（第三人称自由相机） |
| 左下 | 上下文容器（装了什么、裁掉了什么） |
| 顶部 | 关卡号 + 阶段（看 / 改 / 拼）+ 组件清单（十四件里已装几件） |

**没有 HUD 式答疑面板**：求助走世界里的一大块屏（§5.1）。

两条贯穿全局的规则，新功能一律按它们判：

| 规则 | 含义 | 已应用的例子 |
|---|---|---|
| **界面上不放东西，世界里有东西** | 凡是"本来该做成 UI 面板"的，都搬进世界 | 成片在幕布上播、助学文档是石板、求助是一大块屏、组件状态靠方块自己亮；预算表因为不适合放世界而**直接砍掉**，不是缩小塞角落 |
| **一事一物** | 做不同的事，就是不同的物件 | 机械臂管修改 / 扫描器管读取；播放器管看片 / 求助屏管问答 |

**三样东西明确不放**：

- **不放步骤带**——它与视频功能重复；"跑到它了"由世界本身表达（相机跟着 codex 走，它走到哪台组件、那台就亮）
- **不放预算表**——token / ops 仍记进步记录（评分要用），但不在世界里显示
- **不放常驻代码编辑器**——一级二级不需要，一进来就是一屏代码会劝退 8 岁用户

## 四、运行与时间控制

- **一个运行键**在明面上；暂停、单步、慢放（0.5× / 0.25×）、加速（2× / 4×）收进展开菜单
- 单步走的是 `world.step`，是引擎里的真单步（不是把动画放慢）
- **慢放只靠取帧策略**，绝不放大物理步长（spec §7.1）

## 五、卡住了怎么办：三次之后才给提示

**触发阈值**：同一个关卡内尝试失败 **3 次**才开始给提示。依据是 Code.org 的实测参数（其关卡 JSON 里 `hintPromptAttemptsThreshold: 3`）——太早给提示会让人不再思考，太晚就流失。

**三级提示，逐级升级，都不直接给答案**：

| 级 | 给什么 | 锚在哪 |
|---|---|---|
| 1 | 现象 | 世界里那台组件变红，相机自动移过去 |
| 2 | 诊断 | 该组件的 `fail` 说明（来自概念映射的失败表），**用气泡指到具体方块上**，不是泛泛文本 |
| 3 | 代做 | codex 慢速跑一遍同一任务，随时按停接管（§六） |

第 2 级的"锚定到具体方块"抄的是 Code.org 的锚点气泡——泛泛的提示文本对儿童几乎无效。

### 5.1 求助屏：不是 HUD，是世界里的一大块屏

用户裁决：**求助也用一个屏幕方块来交互（其实是一大块）**。

| 项 | 口径 |
|---|---|
| 形态 | 世界里的一块**大屏**，与播放器方块同类（家族二的幕布），但**与播放器分成两块** |
| 为什么分开 | 做不同的事本来就可以分开（用户裁决）。看片是**被动接收**，问答是**主动交互**，两件事各自有一块屏；这也是"一事一物"这条规则的第二次应用——第一次是机械臂管修改、扫描器管读取 |
| 怎么用 | 走到屏前开始对话；agent 的实体走到屏前回答——它的一切行为都是物理形式，这条与机械臂、扫描器一致 |
| 为什么不做成 HUD 面板 | **空间成本就是摩擦**。常驻面板会让孩子反射式地问而不先想；要走过去的一大块屏，只有真卡住了才会去。这正好保护了"三次失败阈值"想保护的东西 |
| 命中范围 | 同一关可反复问；问什么不影响判定 |
| 记录 | 对话与任务运行分开存：它不进 `task` 运行的步记录，但保留下来供评分与复习 |

## 六、代做与接管

任务牌上两个按钮：「我来」/「让它做」。

- 让它做时**慢速可视**、随时按空格暂停并接管
- **代做的运行不参与判定**（spec §7.1）——判定只对学员自己的 `task` 运行做

这条同时是我们对"导入标准答案"的防线：**产品里绝不提供"载入标准装置"或"载入标准解"**。依据是编程猫的反面教材——它把"导入答案"做成了解题路径（`G-教育编程游戏交互.md` 列为最该避免项）。代做与抄答案是两回事：代做是**看着它做、随时接管**，过程全在眼前；导入答案是**跳过过程拿结果**。

## 七、激励：agent 的五维诊断评分

不做星星，不做排行榜，做 **codex 的多维度诊断**（`mini-codex.md` §4.1）：

| 维度 | 看什么 |
|---|---|
| 正确性 | 目标达成没有 |
| 结构 | 流程拆得清不清 |
| 效率 | 步数与改动次数（取自步记录的 `ops`） |
| 鲁棒性 | 边界情况处理没有 |
| 可读性 | 别人看得懂吗 |

出的是句子，不是分数："你在第 7 步把校验放在解析之前，所以字段缺失时先崩了。"

**评分要用另一个 codex 实例**（至少另一次调用 + 另一套提示词），不能是刚替你做过的那个——否则等于自己判自己。

**不给排行榜这件事有两条独立证据**，不是我们的偏好：

- **Turing Complete** 官方 FAQ 设专问解释为什么评分锁到后期：玩家会卡在找最优解，"从网上抄到的最好成绩……对大多数玩家来说几乎不可能，**结果让他们觉得自己蠢并卡住**"（原文 `leaving them feeling stupid and getting stuck`）
- **Scratch** 官方拒绝五星评分（"低分会打击人、可能让用户退出 Scratch"）、拒绝等级制度（"会造成社群里的分裂与冲突"）、拒绝成就徽章（"那会造出一个用这个任意分数评判人的社群"）；替代物是单向的 love / favorite。注：此条经 Scratch Wiki 转引并附官方论坛帖编号，非官方站原文

## 八、进度与解锁

- 进度是**三态**，不是百分比：**看过 / 改过 / 自己拼过**
- 每关装上 2–4 件组件，装完即留在装置上，后续关卡继续用
- 自由沙盒全程可用，不受关卡约束

## 九、回退与存读档

抄 KSP 的双轨：

| 轨 | 用途 |
|---|---|
| **回上一版** | 同一任务的两次运行做 diff（配置、结果、评分各差在哪） |
| **存档 / 读档** | 把当前装置存下来，可以是关卡检查点，也可以是学员自己命名的版本 |

重试成本要低：改一个参数再跑一遍应当是**几秒**的事，不是重新搭场景。

## 十、明确不做的交互

| 不做 | 理由 |
|---|---|
| 弹窗评分、星星 | 孩子会为星星做事，不为理解做事 |
| 排行榜（第一版） | 两条独立官方证据：打击新手、造成社群分裂（§七） |
| 强制打卡、连续天数 | 进度焦虑 |
| 常驻代码编辑器 | 劝退低龄用户 |
| 点错扣分 | 失败是信息，不是惩罚 |
| 游戏内无提示、把人导向外部论坛 | Human Resource Machine 的反面教训 |
| **导入标准答案 / 标准装置** | 编程猫的反面教训（§六） |
| **打卡返现 /「0 元学」** | 天天练被长江日报报道：299 天打卡后提现被拒，还索要身份证、银行卡与刷脸。这类机制把学习变成对赌 |
| **广告与购买弹窗拦截内容** | 洪恩、小猿、Duolingo 差评里最集中的一项；对一个教 Agent 的产品，弹窗本身就是在示范坏交互 |
| 暂停视频提问 | 用户裁决：没必要，视频与练习不互相打断 |

## 十一、国内用户的默认期待（以及我们刻意不同的地方）

中国孩子的交互习惯已经被国内 K12 App 塑造过（依据 `H-国内K12教育App交互.md`）。知道默认期待是什么，才知道哪些地方"故意不一样"是差异化、哪些是纯粹的别扭。

| 国内惯例 | 我们的做法 |
|---|---|
| 3–8 分钟视频 + 约 3 道练习 = 一个知识点，节点标**三星** | 视频 + 动手装组件；进度是**三态**、不给星。**"没有星"必须有替代的完成感**——我们的替代物是装置上多了一台组件、顶部组件清单多一格 |
| 答题后立刻对错 + 解析，答错可重来 | 一致，只是把"题"换成"装置"：拼装合法与否即时反馈，跑一遍就看结果 |
| 金币 / 星星 / 连胜 + 排行榜 | 刻意不同：五维诊断，不给分、不排名（§七） |
| 家长端看"今天学了什么 / 做了多少题 / 正确率 / 该复习什么" | demo 不做家长端；要记下国内家长端的通行内容，v2 再议 |

**一个最接近的先例**：核桃编程的"AI 人机双师"——一节 60 分钟切「讲 10 分钟 → 做 15 分钟 → 随时叫老师答疑 → 下一段」，口号「一学九练」，系统自称判对错 100%、反馈指导 70–80%，真人只做辅导。这是"微课 + 动手"在国内最接近的形态；**我们的配比比它更偏动手**（每关 3–5 分钟视频，之后全是装、跑、改、评）。

**一个可参照的界面样本**：洋葱学园是国内唯一把 **AI 答疑面板与动画课并排放在同一屏**的产品。我们的内置 codex 可以参考这个摆法——但要与"暂停视频提问"区分开：被否决的是**练习打断视频**，而"随时能问 agent"是另一回事（见待补 1）。

## 十二、引用警示（来自调研，避免以后再踩）

1. **「天天练」是两个产品**：乐乐课堂的「天天练」与小猿 AI 内购项「小猿AI学练VIP（原「天天练」）」不是一回事，引用时必须区分
2. **国家中小学智慧教育平台 App 评分 3.41（约 8 万条）**，是同类里最低，主因是强制下载、反复登录、卡顿、教材版本滞后。我们若引用它的课程内容，不要顺带把它当体验标杆
3. 国内 App 的界面证据多为 App Store 官方截图与第三方走查（H 组按 A/B/C/D 标注了来源等级），**没有一次是在真实 App 内操作得到的**

## 十三、待补

1. ~~「随时能问 agent」要不要做~~ **已定**：做，形态是世界里的一**大块求助屏**（§5.1），与**播放器分成两块**（一事一物）
2. 关卡内"三次失败"的计数口径：按同一关卡计，还是按同一组件计（按组件更精确——你知道是哪台机器在挨骂；按关卡更宽松）
3. 存档粒度：存整个世界，还是只存装置与参数
4. 家长端：demo 不做，v2 再议；国内通行内容是"今天学了什么 / 做了多少题 / 正确率 / 该复习什么 / 使用时长设置"，H 组已列清单
5. **落点预测的算力预算**：快进多少步、允许多大误差。误差大了虚影就不可信，而虚影不可信整个拖拽手感就废了；以及长按的判定阈值给多少毫秒
# 2026-09-17 沙盒名称与相机补充

沙盒生成台显示中文资产名，技术 ID 和完整参数继续从点按查看入口读取。名称仅在距相机 22 m 内参与筛选，最多显示四张，按画面中心距离排序并避开名称间重叠；全景主要观察装配形态。名称遵守遮挡，不再穿过机器显示。

Tab 仍轮换原有五个预设。沙盒给这些预设定义独立机位，并用 `focus_offset` 为全景降低注视点；回到工作预设时恢复台面焦点。存档、读档、导出和运行仍沿用原交互入口。

## 2026-09-18 组件工坊操作补充

工坊与 L2–L5 采用中键旋转、右键平移、滚轮缩放。工坊点物件或字砖打开全屏阅读，长按搬运，Esc 取消搬运；PgUp/PgDn 翻页，F 聚焦，Home 全页，Ctrl+S/Ctrl+O 保存与读取布局。F1 是临时场景导航，不常驻 HUD。阅读器增加鼠标按钮，可打开超出数字键范围的语句。旧 L1/沙盒手势保持原接口。

地形加载期：L1 的散块在地形就绪前保持冻结；若就绪回调到达时某块正在被长按搬运，冻结状态由拖拽控制器持有，加载回调不得解除它。松手或取消由拖拽控制器统一处理。
