## 1. 设计选择

玩家走进一片宽阔的平地，面前是一组可以搬动、拆开的明亮功能色仪器。凹进去的工作面承载过程，抬高的脊梁说明结构；七个功能族分别使用青、蓝、黄、橙、紫、绿和石墨色。关掉颜色后，仍能凭开口、梳齿、凹井和叉道认出设备。

整机不再是一堆竖立的大牌子。模块围绕一条可读的回路排列，中心留出操作空地；北侧是模型与记忆，南侧是执行与工具。高件集中在北边，正俯视时不靠立面文字补救。轮廓需要有性格，但不使用天线、烟囱、假螺丝或装饰性工艺件。

本轮确定 14 种模块外形、8 种代码基元外形，以及整机、会话分身和公共界面设施。件数由职责合并而来；它不是组件数量上限，也不替代课程概念清单。

命名直接描述行为或用途：任务信箱、跑圈台、行程表、记忆架、传话筒、点子井、工具架、检票口、干活台、储物柜、回音盘、交卷台、分头桥、体力尺。技术 ID 用 `agent_`，代码基元用 `code_`，公共设施用 `studio_`；这些是新设计 ID，尚未写入资产注册表。

## 2. 统一造型与计量

### 2.1 尺寸、坐标与材质

U = 0.5 m 标准方块，q = U/2 = 0.25 m。文中的外形尺寸顺序一律为**宽 X × 深 Z × 高 Y**。每件的局部原点在西北底角，X 向东、Z 向南、Y 向上。盒体用最小角及尺寸定义，六个面均为 q 的整数倍；主体总包络为 U 的整数倍。整件原点摆在 q 格上，旋转只有 90° 整数倍。

部件中心由六面反算，可以是 0.125 m 奇半格。此项遵循《方块体系》2026-09-17 三修，校正交接里“部件中心全部 n×0.25”的简写；不恢复已经废除的半嵌贴面。图册里的盒体数据是本轮**尺寸与拼接真源**，单位为 q；设计卡以米给总尺寸。

外形先用 BoxMesh 搭建。裸露表面最终采用现行 45°×0.05 m 向内倒角，不改包络；倒角网格沿用已裁定的第二波施工方式，不能声称“倒角后仍全部为原生 BoxMesh”。数字、线条、端口箭头均画在材质上，不新增薄片。图册暂以素盒表达占格。

|---|---|---|

| MEMORY 记忆与变量 | #4279d4 | 记忆架、储物柜 |
| CORE 模型与计划 | #f2c43d | 点子井、行程表 |
| ACTION 工具与执行 | #ef743b | 工具架、干活台 |

### 2.2 计数物、结构物与代码块

0.5 m 立方体继续严格表示 1 token 或 1 样本，同一教学视图只选一种量纲。机器底座、代码基元与消息包不能冒充这种计数体。代码基元的最小外包络为 1×0.5×0.5 m，顶面有长向槽，与计数立方体明显不同。消息只以印在槽面的条带与 UI 记录显示，不做“一个消息 = 一个 token”的运动方块。

真实请求可能有数千 token，默认读数显示在字砖或详情里；计数演示模式才逐个摆标准立方体，并保留真实总数和分页位置。不能把 10 个装饰方块标成 1000 token，也不能从响应字符数推测 token 用量。`usage` 缺失显示“未提供”，不显示 0。

### 2.3 信息面、连接与状态

顶面必须读到当前步骤、输入方向、输出方向和运行状态。所有**世界内文字**都放进同一 `studio_text_tile` 字砖系统：地面字砖为主，也可作为同类实体嵌入顶面和立面。取消“名字必须在立面”的限制；名字在南侧地面字砖始终可见，立面只重复短名，不新增悬浮标签。颜色与无字纹样可直接画在壳体上。

字砖外框为 1×0.5×0.5 m，地面安装时全部埋到 y≤0，顶面齐平。小的功能刻度合并到一块砖的纹理里。原草案 0.5×0.25 m 太窄且主体包络不合 U 格，故不采用。两块及以上字砖沿 X 拼接承载长名字，绝不横向压缩汉字。

连接带嵌于地面，宽 0.5 m、每段长 0.5 m、实体深 0.5 m，顶部齐平。用深色底和材质箭头区分流向；端口最小开口宽 0.5 m。数据流为青绿细线，执行路为珊瑚短划，异常回流为叉纹加青绿返回线。线只在邻近插口连接，不从机器中穿过；交叉处用纸白断口区分，不额外堆高桥梁。整机示意的连接线是逻辑关系，施工时仍需路由。

| 状态 | 顶面表达 | 时序 |
|---|---|---|
| 空闲 | 深色槽与空方框 | 静止，不呼吸发光 |
| 排队/等待 | 两条平行短线，字砖写“等待” | 网络等待不冒充执行 |
| 工作中 | 当前格实心、短划前进 | 有真实事件才前进一步；不捏造完成百分比 |
| 成功 | 一枚 SUCCESS 实心方印 | 保留至下一次运行 |
| 失败 | 一枚 ERROR 叉纹与错误短名 | 原始错误保留在详情；其它位置不全变红 |
| 停止请求 | 双竖杠与“等待本步结束” | `interrupt_switch` 在下一圈检查，不能承诺立即取消请求 |

状态格均为贴在现有表面的材质区域。静止状态也可读；减弱动画时不丢信息。搬动组件时整组一起移动，不能仅移动根节点而让物理带面留在原点。

## 3. 模块设计卡

以下所有模块继承 §2 的字砖、端口、状态和尺寸规则。图册可按中文名选择每一件；俯视剪影与正视剪影从同一盒体计算，不分别美化。模块卡中的“内部”表示点开后的功能拼接，不表示源码已经接到游戏。

### 01 · 任务信箱 `agent_task_dock`

**用途与形状。** 接收一轮任务。2×1.5×0.5 m；顶视为向南敞开的浅 U，正视是一层低槽，中央 PAPER 面接住新任务。壳体 SHELL，凹槽 INK，入口 SIGNAL。尺寸链：底板 2×1.5×0.25；两侧各宽 0.25、高至 0.5；后挡深 0.25。

**信息与状态。** 顶面字砖显示本轮编号及“新任务/接着聊”；南侧地砖显示名字，立面仅有入口纹样。接收时入口出现青绿实心格；缺任务时保留空槽并在详情说明。`reset=True` 清步骤，`reset=False` 接续步骤；两者每轮都重建系统提示。不得把 reset 画成清空执行变量。

**内部。** 任务基元、系统提示装配基元、重置分支、`TaskStep` 记录基元依次拼接。详情能分别看任务文字、图片、附加参数与当前系统提示。

### 02 · 跑圈台 `agent_loop_table`

**用途与形状。** 决定继续执行还是结束。2×2×0.5 m；顶视为开向南侧的方回路，正视为双低臂；后端珊瑚横梁与前端缺口形成方向。底板厚 0.25，回路边宽 0.25、高至 0.5。中部空白承担当前步的字砖，不放装饰核心。

**信息与状态。** 顶面显示“第 3 / 最多 20 步”和下一站，南侧字砖承载名字。工作时当前段实心；达到上限时显示“步数用尽”，转到尽力回答支路，不能显示正常完成。停止拨块在地面详情中可点按，未完成的本步标“停止已请求”。

**内部。** while 基元接停止检查、计划判断、执行步、finally 记录与终点判断。失败回写与成功回写都先经过记忆架。计划生成错误与 `AgentGenerationError` 不画成必然可自愈；能否继续以真实事件为准。

### 03 · 行程表 `agent_plan_steps`

**用途与形状。** 承载重看计划的调用。1.5×1.5×1 m；顶视为三条等宽横带，正视是一级一级抬高的阶梯。深度三个 0.5 段，高度依次 0.5、0.75、1；SHELL 主体、PAPER 读面、SIGNAL 短标。

**信息与状态。** 顶面分“现有事实/下一步/待验证”，内容点按才展开；南侧地砖显示“行程表 · 每 N 步”，数字也可嵌在立面字砖。默认关闭时显示“未启用”；启用后第 1 步以及每 N 步重看计划。生成失败在当前阶标叉，旧计划留存且标旧。

**内部。** 间隔判断基元、历史读取、一次模型请求、`PlanningStep` 写入。展示的是模型返回的计划文本，不是不可见的内部思考。

### 04 · 记忆架 `agent_memory_rack`

**用途与形状。** 保存系统提示与步骤列表。2.5×1.5×1.5 m；顶视是四槽梳齿，正视是四个深色档案口。底板厚 0.25，背脊深 0.25、高 1.5；隔板宽 0.25，每槽净宽 0.25 或 0.5，由图册坐标固定。骨架 STRUCTURE，隔板 SHELL，槽底 INK，当前写入点 SIGNAL。

**信息与状态。** 顶面四类槽纹区分任务、动作、计划和系统提示；物理槽是索引，不表示只可存四条。字砖写实际条目数；失败的动作也保留，原记录带叉。正面槽口不写长日志。reset 清除步骤列表，系统提示保留；每次 run 另行更新系统提示。

**内部。** 系统提示槽与可增长步骤列表分开。选中动作记录后，详情显示 13 个字段：步号、起止时间、模型输入快照、工具调用、错误、原始响应、模型文本、代码、观察文字、观察图片、动作结果、用量、终点标记。历史浏览的分页不等于发送时裁剪。

### 05 · 传话筒 `agent_message_table`

**用途与形状。** 将历史拼成模型消息。2.5×1.5×0.5 m；顶视为五路进入、一路退出的梳口，正视为低台与后端齿列。底板厚 0.25，五个入口以 0.25 格划分，右端青绿出口宽 0.5。主体 PAPER，通路 INK。

**信息与状态。** 顶面槽纹对应 system、user、assistant、tool-call、tool-response，文字进入地面字砖或详情。每次请求显示“全部历史”，消息条数不替代 token 数。消息清洗将后两角色转换并合并相邻同角色；错误观察附带重试提示。失败时停在转换前后对照，不吞掉原始内容。

**内部。** 系统提示读取、列表遍历、角色转换、相邻合并、请求封装。20,000 字符截断属于写入观察的处理，不画成这里的总上下文窗口。全量回放仍是按各 Step 的 `to_messages()` 序列化，不是把 13 个字段原样全部发给模型。

### 06 · 点子井 `agent_model_well`

**用途与形状。** 表示一次模型请求。2×2×1.5 m；顶视为厚框方井，中心露出 0.5×0.5 的琥珀读区；正视为左右肩和低中段。底板高 0.5，外框宽 0.5、高至 1.5，后肩与两侧一致；中央台高 1，最高边缘不盖住顶视内容。主体 SHELL，内壁 INK，中心 CORE。

**信息与状态。** 顶面只显示“等待/接收/完成/失败”和输入输出用量，名称在外侧字砖。请求中琥珀常亮，流式文字在详情逐步出现；没有确定进度时不画百分比。限流时显示等待与重试次数；普通错误不画成自动重试。

**内部。** 消息入口、工具菜单入口、HTTP 请求、响应信封、流式片段归并、用量读取。井底到此停止解释模型内部；不能给它假装的 AST、注意力动画或思维链。重试默认最多 3 次尝试，60 秒起、指数退避加抖动，不是“初次之外再重试 3 次”。

### 07 · 工具架 `agent_tool_rack`

**用途与形状。** 注册可调用工具与子智能体。2.5×1.5×1 m；顶视为 E 形三挂位，正视是单高背脊与三低托。背脊宽 0.5；三个挂位长 2、深 0.25，高 0.5，间隔为 0.25 或 0.5。背脊 STRUCTURE，托 SHELL，插口 ACTION。

**信息与状态。** 顶面显示已注册/未注册的槽纹，地砖承载工具名字；`final_answer` 有固定挂位且不能被当成普通成功灯。缺工具时对应空插口加叉，不把整架染红。挂位可重复扩展，三槽是可见分页，不是工具数量限制。

**内部。** 每个工具卡提供 name、description、inputs、output_type、可选 output_schema。两条不同的输出分别去系统提示中的说明书和执行器的函数表；ToolCallingAgent 的模型请求还携带完整工具 schema 菜单，CodeAgent 不因此被画成同一种 API 工具请求。普通函数经 `@tool` 的注解/docstring 生成 schema。子智能体插口点开进入子整机，并保留父调用位置。

### 08 · 检票口 `agent_argument_gate`

**用途与形状。** 检查调用名称与参数。1.5×1.5×1 m；顶视为两个错位 L 形块，正视是一高一低的夹口。左肩宽 0.5，高 1；右肩宽 0.5，高 0.5；中间净通道宽 0.5。SHELL 双肩、INK 通道、ACTION 入口。

**信息与状态。** 顶面分别以缺口、空槽、错纹提示未知工具、缺必填、类型不符。失败调用停留在入口，详情突出具体参数。通过仅说明参数校验成功，不保证工具结果正确、安全或满足 output_schema。

**内部。** 名称查询、必填检查、类型检查、调用出口。一项失败即可终止本次调用并回写错误；不能把这件做成只按颜色分拣的装饰门。

### 09 · 干活台 `agent_execution_table`

**用途与形状。** 显示 Python 代码被逐节点求值。2.5×2×1 m；顶视为向南敞开的 U 型工作台，正视左侧高背脊、中央低槽、右侧短臂。底板厚 0.25，侧臂宽 0.5，后沿深 0.5；中央净工作区 1.5×1.5。SHELL 外壳、INK 工作面、ACTION 当前行。

**信息与状态。** 顶面嵌字砖显示当前逻辑行与“运行/停止”；详细源码在点击后的展开工作区。错误在对应代码块留下叉纹，详情保留源码片段。解释器不是 `exec`，不支持的语法直接显示“此语法未实现”。

**内部。** `ast.parse`、语法分派、各 `evaluate_*`、函数/变量查找、输出捕获、错误包装。`python_interpreter` 在主循环里是一种工具调用；打开它才看到代码基元。语法节点求值与行号不是一一对应，当前行可以连续亮多次。

### 10 · 储物柜 `agent_state_cabinet`

**用途与形状。** 存放跨步保留的执行 state。1.5×1.5×1.5 m；顶视为双列封闭方柜，正视为两个高抽屉和中间深缝。主体两个 0.5 宽柜体，高 1.5，中间缝宽 0.5；底座厚 0.5、贯通全宽。SHELL 柜面、STRUCTURE 基座、SIGNAL 写入记号。

**信息与状态。** 顶面显示“变量数”与本步修改标记；南侧字砖写“储物柜”，立面每格只重复短变量名。读取不移动实体计数方块；失败赋值保留旧值并展示写入失败。历史 reset 不暗示这个柜子清空；新建执行器与清历史是两个动作。

**内部。** 名称、值、类型、最后写入步骤；函数查名先查 state，再查静态工具、自定义函数，另有内建错误类分支。源码还存在 `evaluate_name` 近似匹配回退，详情如实显示最终匹配，不能教成永远严格精确查名。

### 11 · 回音盘 `agent_observation_tray`

**用途与形状。** 接住工具结果、print 输出与错误。2×1×0.5 m；顶视是一条横槽与右端独立回执格，正视为低长盘。底板厚 0.25，后沿深 0.25，回执端宽 0.5；PAPER 读面、INK 槽、SIGNAL 回执。

**信息与状态。** 顶面分文字条纹、图片方框、音频波形三种材质纹样；错误加叉。`print` 进入这里的观察缓冲，不能画成系统终端输出。截断时字砖写“已截断”，详情提供保留长度与实际可得原文范围；没有保存原文时不能承诺展开完整内容。

**内部。** 输出包装、文本截断、图片/音频 state 引用、观察回执与错误文本。回执送记忆架并进入下一次消息；媒体本体与模型实际收到的消息分别可查。

### 12 · 交卷台 `agent_answer_dock`

**用途与形状。** 承载 `final_answer` 与终点状态。1.5×1.5×0.5 m；顶视是右上缺角的方台，正视为一长一短的低阶。底座 1.5×1×0.25，后侧短台 1×0.5；读面高至 0.5。PAPER 台面、STRUCTURE 基座、SUCCESS 方印仅在正常完成后出现。

**信息与状态。** 顶面字砖显示“已交付”或“步数用尽 · 尽力回答”；答案全文进入右栏。失败的最终检查在交付前保留叉纹，不盖成功章。

**内部。** `final_answer` 工具、`FinalAnswerException` 控制流、最终检查与 `FinalAnswerStep`。这个异常继承 BaseException，一般 `except Exception` 不截获；它终止的是本次代码求值/agent 流程，不是游戏进程。

### 13 · 分头桥 `agent_parallel_bridge`

**用途与形状。** 展示同一步中的多工具调用与汇合。2.5×2×0.5 m；顶视为三条独立平行槽、两端共用横条，正视为三个低齿口；槽高 0.5，两端汇合条厚 0.25。STRUCTURE 汇合条、SHELL 槽、ACTION 各调用入口。

**信息与状态。** 顶面每槽有独立调用状态；按真实返回次序更新，未完成槽保留“等待”。某一路失败不伪造全部成功或整体立即取消。三槽是可见分页，调用数量与线程上限在详情中显示。

**内部。** 工具调用列表、线程池提交、完成回收与结果关联。父会话分身留在跑圈台，不复制成多个 agent；工具调用是任务标记。真正的子 agent 才有独立形象和记忆。

### 14 · 体力尺 `agent_budget_rail`

**用途与形状。** 显示执行器的三个资源边界及安全策略。2.5×1×0.5 m；顶视是三根不同长度的平行尺，正视为低梳条；基座厚 0.25，尺高至 0.5。PAPER 标尺、INK 刻度、ERROR 超限叉纹。它可以贴干活台拼接，也可独立放置；图册将它置于东南空区，避免索引文字遮挡干活台。

**信息与状态。** 三条分别显示节点求值、while 圈数、墙钟时间；默认阈值 1000 万、100 万、30 秒。没有实时计数事件时只显示上限与最终触发项，不填虚构进度。安全拒绝用“禁止导入/禁止访问/语法未实现”文字区分，不能只显示笼统失败。

**内部。** import 白名单、危险模块/函数限制、dunder 限制及三个独立检查点。详情展开当前有效策略，含额外授权导入；这不是安全隔离保证，也不表示 CodeAgent 中的 Python 获得任意系统权限。超限后对实际执行的取消效果必须经接线测试，视觉不能先承诺强制杀进程。

## 4. 三层递归与代码基元

整机是可移动模块的组合，模块是有输入输出的代码基元组合。点按先打开详情中的“查看内部”；选择后在独立展开工作区显示内部拼接，外层留一个静止轮廓与返回路径。运行中的世界继续执行，展开区显示同一实例的事件，不复制运行。运行时内部编辑暂存到下一轮生效，避免边执行边换代码。

“一行一块”定义为**一个逻辑语句对应一块**：多行函数调用仍是一块；`a=1; b=2` 是两块；空行与注释显示在源码旁，不产生可执行件。if/for/while/try/def 等头部本身是一块，语句体排在其凹口下面，不增加第四种产品层级。表达式 AST 节点是详情里的求值高亮，不强造“一个 AST 节点 = 一行”。未经支持的语法保留原行并显示失败，不能悄悄转换。

| 显示名与 ID | 俯视 / 正视剪影；尺寸 X×Z×Y | 表面与状态 | 点开内容及示例 |
|---|---|---|---|
| 赋值块 `code_assign` | 单长槽 / 低台；1×0.5×0.5 | SHELL 两侧、SIGNAL 目标格；失败叉纹 | 源码行 `total = a + b`、目标与实际值；不把槽纹算成 token |
| 调用块 `code_call` | 前端缺口 / 双短肩；1×1×0.5 | ACTION 入口、PAPER 输出格 | `search(query)`，实际函数名、参数及返回；失败定位参数或调用 |
| 判断块 `code_branch` | T 分叉 / 低三段；1.5×1×0.5 | 两支 INK，真实选中支 SIGNAL | `if ready:`；条件结果及未走分支，不能提前点亮两边 |
| 循环块 `code_loop` | 开口方框 / 双臂；1.5×1.5×0.5 | ACTION 当前段、PAPER 次数砖 | `while pending:` / `for item in items:`；体内语句与真实次数 |
| 定义块 `code_define` | 梳形 / 高背低托；1.5×1×0.5 | SHELL 背脊、INK 参数槽 | `def solve(x):`；定义时不执行函数体，调用后高亮对应实例 |
| 取值块 `code_read` | 双平行槽 / 双低条；1×0.5×0.5 | SIGNAL 读口、PAPER 值面 | 独立表达式或导入语句；实际查名、索引、导入策略在详情区分 |
| 异常块 `code_guard` | L 形 / 单肩；1×1×0.5 | ERROR 仅在捕获或抛出时显示 | `try:` / `raise ...` / `except ...` / `finally:` 分别是实例；finally 不能被画成失败才走 |
| 返回块 `code_return` | 尾端封闭槽 / 低台；1×0.5×0.5 | PAPER 结果面，完成方印 | `return result`；普通 return 与 `final_answer(...)` 调用保持不同，后者属于调用块 |

这八种是视觉语法，不是解释器支持清单。所有 30+ `evaluate_*` 按**实际所属语句**进入对应代码块；比较、算术、布尔、容器、属性等嵌在语句详情。生成器表达式、推导式、上下文管理等特殊语句先沿用对应控制/赋值外形，并展示准确 Python 语句种类；实现前以解释器分派表做逐项适配，不能因已有图标而宣称支持。基元外形仅用不小于 q 的实盒与表面纹样。

基元名字与源码放相邻字砖或详情，代码不塞进 1 m 壳体上。侧面统一为 SHELL/STRUCTURE 分层，身份不依赖侧面。语句状态继承 §2，内部已到逻辑语句底，不再套无穷空盒。

## 5. 整机、会话分身与公共设施

### 5.1 智能体工作场 `agent_workcell`

预置占地 14×10 m，留白不少于一条 1.5 m 主通道；不是必须整体占满的巨大实心地基。组件最高 1.5 m。任务信箱与交卷台在南边相邻，北侧依次放记忆架、传话筒、点子井；东侧放检票口、工具架、分头桥；干活台与储物柜在西南，跑圈台在中心偏北，行程表紧邻跑圈台。图册提供全部 14 件的可检查布局，设施之间的线是功能关系。

主循环每轮把历史送入传话筒，再请求模型；返回后调用检票口和干活台/工具架，回音盘回写记忆架，跑圈台决定继续或交付。计划支路也调用同一模型接口。体力尺属于执行器路径，不是所有工具的全局时间限制。

子整机作为工具架的一项注册。折叠状态仅显示其接口座，点开进入子工作场；父子具有明确的会话路径与返回入口。不能把子整机等比缩到 0.5 m 内再谎称标准方块仍是 0.5 m，展开使用独立局部空间与原始度量。

### 5.2 会话分身 `studio_session_walker`

外包络 0.5×0.5×1 m。下部是一块 0.5 m 标准尺度的壳体，上部是同宽的方形显示面；顶视是整方形中一条偏向前端的 SIGNAL 条带，正视是短身、深色面窗与两枚静止方脚。面窗与眼睛为材质，无圆头、触须或悬浮姓名。结构盒从 q 格搭建，步行动画使用整件平移和纹理步态，朝向按 90° 切换，避免关节旋转违反几何约束。

原 0.75 m 草案改成 1 m，以满足主轮廓 U 格。它是执行位置的指示者，不把机器搬到自己身上。前端工具身份只换面窗纹样，不外挂改变包络的细碎工具。顶面 2×2 格纹编码与右栏会话头像对应，不只靠颜色区分；不把编码方格解释成 token。

移动是事件回放，不能拖慢实际模型调用。事件快于走路时，目标机器立即变为工作中，形象随后到达；详情显示真实时间。失败时形象停在对应件旁，面窗叉纹；请求停止时双杠。并行工具没有第二个 agent 形象，真实子 agent 才另建形象。

### 5.3 字砖、连接带与微课地屏

`studio_text_tile` 与 `studio_flow_strip` 尺寸见 §2。字砖顶视为纸白长方形，正视仅在顶面安装时看到 0.5 m 实体侧面；地面安装埋到 y≤0。字砖不闪烁，点击进入所属组件详情；内容无效时显示短横线与“未提供”，不编造默认值。内部是统一字体、排版宽度、字号等级与所属实体引用，无 Python 运行流程。

`studio_lesson_screen` 外框 9×5.5×0.5 m，埋入地面；内部有效画面 8×4.5 m，严格 16:9，四边各 0.5 m 框。原约 14×7.9 m 改为这一尺寸以落格、保比例，并留出世界建设面积。顶视为深色横屏，侧视与地面齐平，不立大墙。PAPER 边框、INK 播放面、ACTION 播放控件均为贴面；文字是屏幕内容，不作为漂浮世界标签。

屏幕点按进入观看模式，相机正俯视、画面保持比例；退出后仍是原世界位置。视频用 SubViewport→ViewportTexture 路线，播放失败显示错误与重试按钮，不无限旋转；界面必须支持字幕、静音、暂停与返回。具体视频格式和音频接线在实现期实测，本轮不声称 Godot 原生能直接播放任意 MP4。它的内部详情是播放器状态，不把解码过程装成教学 Python 基元。

### 5.4 三栏应用壳 `studio_shell`

桌面 1440 px 参考：左栏 224、中栏弹性 856、右栏 360；最小完整三栏宽度 1200。低于 1200，左栏收为可展开列表；低于 900，中间世界与对话以明确标签切换，世界继续运行。世界获得焦点时按 Tab 切换沉浸/三栏，输入框内 Tab 保留焦点导航，Esc 先退出详情再退出沉浸。

左栏只放“世界管理者”、会话列表与设置。中栏顶端是场景路径、实时/回放标记和查看内部返回入口；不能把截图误标实时。右栏有对话对象名、状态、消息与输入框。世界管理者无 3D 身体，头像采用四个矩形构成的空心框，颜色为 UI primary；普通 mini codex 会话头像沿用会话分身的顶面格纹。

世界内点按先在右栏打开组件详情页签，对话仍可切回。参数用方形拨块拖动刻度；方形拨块沿轨道滑动，不画违反盒体规则的圆盘。键盘方向键提供等价调整，Esc 取消、Enter 确认，不要求键盘输入数字。对话输入仍可以打字，原“参数不键入数字”不应误扩展为禁止对话。

主题取自当前 DeepTutor `globals.css`，不是另扩世界色盘。Cream 背景 #fdfcf9、文字 #1c1816、次级面 #f5f2ea、线 #e6decc、primary #b0501e；Dark 对应 #1a1918、#e8e4de、#2a2725、#3a3634、#d4734b。字体优先系统中文无衬线，正文字号 14–16 px，操作区至少 36 px、触屏 44 px。选中靠一条侧边线与浅底色，不堆阴影卡片；对话正文左对齐，不把整个答案包进彩色气泡。
