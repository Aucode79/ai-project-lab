## 1. 目标与验收

**目标**：概念与方块建立稳定对应；微课的每个画面片段都是沙盒资产的捕获结果；沙盒同时是可被真实 Agent 通过 MCP 操作的物理小世界；视频与动手合到一处。

**v1 验收（四条）**

1. **映射闭合**：demo 四集（E49–E52）涉及的全部大纲条目，在概念映射里都有对应方块；没有"讲了但没东西可演"的条目
2. **渲染器确定性**：同一帧输入渲染两次，输出像素一致（这是渲染器质量，与物理无关；物理结果本身不承诺可复现）
3. **片段可复用**：**从 E50 起**，单集 ≥6 个片段且 ≥2 个来自既有资产库。E49 豁免（此时资产库尚不存在）
4. **Agent 可接入**：内置 agent（mini codex）通过世界工具完成一次"放置 → 连线 → 设参 → 运行 → 观察"，全过程落成步记录，且该记录足以判定任务是否达成

**豁免口径**：只有**全由陈列概念构成的集**不受验收 3 约束；含可操作概念的集照常要求 ≥6 个片段，陈列概念的片段不计入。

## 2. 形态：沙盒的三个身份

| 身份 | 对谁 | 产出 |
|---|---|---|
| **资产车间** | 内容生产 | 承载概念的小结构，可单独打开、单独捕获 |
| **可交互小世界** | 内置 agent 与学员 | 有物理、有工具面，动作有真实后果 |
| **练习场** | 学员 | 改一个旋钮看结果；修坏掉的配置；对照观摹基线 |

**播放器方块是交付面**（`docs/10-契约/方块体系.md` §5.1）：学员在沙盒里走到幕布前看这一集的成片，看完当场在同一个世界里跟着做一遍。**微课不是在这里拍一集，而是从这里取零件**：一集 = 若干资产片段（透明背景捕获）+ 图层（公式、表格、代码、字幕）+ 配音 + 播放器里的成片。

**内置 agent 的两个身份**（详见 `docs/10-契约/mini-codex.md`）：它是原 spec §4「观摹」阶段的那只手，也是「接管」阶段的交还对象；组件本身即 U10 四集的教学对象。

## 3. 方块体系、渲染分工与资产

### 3.1 方块清单

权威清单在 [`docs/10-契约/方块体系.md`](../方块体系.md) §二与 §五，**共 12 种**：

- **家族一 1 种**：代码结构方块，形状有直线 / 分岔 / 带环 / 扇出 / 汇聚五种拓扑变体。可操作、可拼装、**必须能导出 Python**
- **家族二 11 种**：`chart_` 图表、`table_` 表格、`flow_` 流程/拓扑图、`text_` 文本/条目、`concept_` 概念示意图、`formula_` 算式/推导、`timeline_` 时间轴/进度、`dialogue_` 对话、`output_` 图像/输出、`player_` 播放器、`fallback_` 兜底展示。只读或展示

**分界规则**：能被学员写代码算出来的归家族一，只能读不能算的归家族二。

**三级粒度**：一级是出厂预设装配（整段典型工程流程，无需编程基础，对应观摹）→ 二级拆开露参数（接管）→ 三级自由拼装并导出 Python（手写）。

不计入方块类型的：`版式/分区`（集号、进度条、字幕条等固定版式，由图层承担）与覆盖统计里的"其他"（归入兜底展示）。

### 3.2 渲染分工

判据一句话：为了"看关系与变化"的元素走沙盒，为了"读符号"的元素走图层。

| 走沙盒（资产片段） | 走图层 |
|---|---|
| 因果与顺序（谁给谁、第几步、堵在哪） | 公式、下标、单位 |
| 量与比例（矩阵格、柱高、曲线点、排序条） | 表格文本、代码、结论条 |
| 状态与失败（闸门关闭、良品率、重试） | 定义、题面、选项、固定版式 |

图层用 HTML/LaTeX 渲染成带透明通道的序列，按 `t` 与片段对齐；字体与色板沿用大纲 §7.2。固定版式（左上集号与标记、右上进度条、底部字幕条）由图层负责。

**禁止**：用方块拼公式、用方块拼代码。出现这种情况说明分镜该改，而不是该放宽这条。

### 3.3 三层资产库

| 层 | 前缀 | 例子 | 复用范围 |
|---|---|---|---|
| 基础件 | `base_` | 方块、轨道、容器、闸门、插槽、连线、标签牌 | 全部集 |
| 机械 | `mach_` | 传送带、分流器、堆叠架、计数器、校验门 | 大部分集 |
| 概念装置 | `conc_` | `conc_attn_beam`、`conc_batch_belt`、`conc_tool_slot_gate` | 按章建，跨集复用 |
| 展示件 | `chart_` / `table_` / `flow_` / `text_` / `concept_` / `formula_` / `timeline_` / `dialogue_` / `output_` / `player_` / `fallback_` | 家族二的 11 种 | 跨集复用 |
| 装饰件 | `fx_` | 碎屑、粒子、飘浮方块 | 由物理驱动 |

验收口径：用基础件与机械在 30 分钟内拼出一个新的概念装置。

### 3.4 捕获规范

| 项 | 口径 |
|---|---|
| 独立场景 | 每个资产可单独打开与渲染，不依赖所在集的布景 |
| 相机 | **第三人称轨道相机为主，相机自由换**（参考《围攻》）：绕主体旋转 / 平移 / 缩放 / 跟随；播放、暂停、慢放、加速与相机并列。预设位是**存下来的姿态**，不是限制 |
| 预设位词表 | `iso`（正交等距，讲结构时用）、`front`、`top`、`close`（特写）、`vista`（远景，存在感用）。资产在 `shots` 里声明自己支持哪几个；**分镜轨记录自由相机的关键帧，不限于预设位** |
| 动作词表 | `idle`（静止展示）、`run`（一次完整运转）、`open` / `close`（开合类）、`fail`（失败路径）。**动作词表就这五个** |
| 片段时长 | 按（机位，动作）分别声明，不统一取"一个动作周期" |
| 背景 | 透明通道输出，光照与主题一致 |
| 画幅与帧率 | 1920×1080，25 fps |
| 输出 | 带 alpha 的 PNG 序列（或 ProRes 4444），逐帧落盘 |
| 索引路径 | `assets/{assetId}/{机位}_{动作}/` |
| 物理与捕获 | 依赖物理的片段**不必**先烘焙，直接实时跑、直接捕获。只有需要两个机位拼接同一段时才先 `studio.bake`（§7.1） |

静态讲解抽单帧，动态讲解出片段，两者同源。

## 4. 概念 ↔ 方块映射

映射是唯一事实源：微课按它取片段，沙盒按它摆放机械，诊断题按它的失败表现命题。**拆成两份记录**，因为一个概念可对应多个资产，而参数属于资产本身。

### 4.1 id 与权威

- `conceptId` 引用 `outline_index.json`，**不自造**；样例 id 在生成该文件时校验，不预先断言
- 概念侧字段（`knob` / `observe` / `fail` / `examType`）的语义以**原 spec §5.1** 为准。但**§4.4 的结构化 `observe` 是本文的强制要求**，不因"以原 spec 为准"而豁免
- `label` 用官方条目全称（例如「四-优化设置：基于批次数据的训练方法」，不截断）

### 4.2 concept 记录

```
conceptId     # 引用 outline_index.json
label         # 官方条目全称
episodes      # 用到它的集号
kind          # operable（可操作）| exhibit（陈列）
examType      # 概念辨析|计算|程序填空|程序阅读|论文阅读（可空）；片尾题与诊断题的归属依据
knob          # [{key, 范围}]，可为空；只声明范围，默认值在 asset
assetIds      # 指向 asset 记录，1..N
knobBinding   # {knobKey -> {assetId, paramKey}}；资产级绑定，实例解析见 §4.5
observe       # [{observeId, targetRef, kind, expect}]；结构化（见 §4.4）
fail          # [{failId, 条件, 可观测表现}]；failId 全局唯一，命名 {conceptId}:{n}
contrast      # knob 为空时的替代：与哪个概念易混、边界在哪
caption       # 默认字幕（图层渲染器的数据源）
formulaRef    # 需要时挂的公式（图层渲染器的数据源）
```

**两类概念**：`knob` 非空且能写出 `observe`/`fail` 的是**可操作概念**（配可操作资产，进片尾自测题）；`knob` 为空的是**陈列概念**（配陈列资产，`fail` 由 `contrast` 替代，**不挂假旋钮**）。

### 4.3 asset 记录

```
assetId       # {层}_{语义}，层取 §3.3 的前缀
kind          # parametric（可操作）| exhibit（陈列）
blockTypes    # 该资产的方块类型，1..N（取自 §3.1 的 12 种）；**每集方块覆盖的数据源**
conceptIds    # 服务的概念，1..N
footprint     # 占地格数
anchor        # 放置锚点
ports         # [{id, kind, dir}]；资产级定义，实例寻址见 §4.5 与 §5
defaults      # 出厂参数值；**默认值的唯一来源**
shots         # [{机位, 动作, duration, 输出路径}]；机位与动作取自 §3.4 的词表
```

`blockTypes` 是验收 1（映射闭合）与"每集用到几种方块"的唯一数据来源；`kind` 决定能否被 `world.set_param` 改参数、能否导出 Python（家族二不可导出）。

### 4.4 observe 必须结构化

`observe` 不能是散文，否则 `highlight` 无法推导：

```
observeId   # 本概念内唯一
targetRef   # 模板引用：{assetId} 或 {assetId}:{portId}；运行时按 §4.5 解析成实例
kind        # value | shape | state | motion
expect      # 期望的可观测结果，供断言与高亮
```

`highlight` 由此推导，不手工填；没有对应对象时为空。`fail` 的判据必须能被状态层判定。

### 4.5 映射是资产级，消费者是实例级

映射表**不写实例 id**（同一资产可能被放多份）。解析规则：

1. 世界初始化或练习场任务声明一张**实例绑定表** `bindings: {assetId -> entityId}`
2. `world.set_param(entityId, key, value)` 的 `entityId` 由绑定表给出；`knobBinding` 的 `assetId` 经绑定表解析
3. `observe.targetRef` 的模板经绑定表解析成 `entityId` / `portRef`，再推导 `highlight`
4. 同一资产放两份时，绑定表按 `#{序号}` 区分；**没有绑定的实例不参与操作与高亮**

### 4.6 样例（id 生成时校验）

| conceptId | 概念（官方条目） | assetId | kind | 旋钮 | observe | fail |
|---|---|---|---|---|---|---|
| c3.1 | 三-注意力机制 | `conc_attn_beam` | parametric | d_k、温度 | shape：束状连线粗细随归一化变化 | 权重全部塌到同一个 key |
| c3.2 | 三-主流架构 | `conc_arch_swap` | parametric | 装配方式 | state：数据流可见方向改变 | 给自回归任务装了编码器架构 |
| c4.5 | 四-优化设置：基于批次数据的训练方法 | `conc_batch_belt` | parametric | batch size | value：每批方块数与总步数 | 不能整除样本数时未取整 |
| c10.3 | 十-智能体工具使用 | `conc_tool_slot_gate` | parametric | schema 字段集 | state：闸门开或关 | 返回字段集与 schema 不等 |
| c1.1 | 一-人工智能相关概念定义 | `concept_rings` | exhibit | — | — | contrast：机器表现出智能行为 ≠ 机器拥有智能 |

**硬规则**：一个资产必须能回答"它服务哪个概念"，不允许纯装饰资产进入微课（装饰件 `fx_` 不是资产，由物理驱动、只进轨道）。

## 5. 实体与片段命名

| 名字 | 形式 | 用途 |
|---|---|---|
| `entityId` | `{assetId}#{序号}` | 资产实例。世界、步记录、轨道三处共用 |
| `fxEntityId` | `fx:{emitterAssetId}#{序号}` | 装饰实体（碎屑、粒子）。不服务概念，但会被物理影响、要写进轨道，因此必须有合法 id |
| `portRef` | `{entityId}:{portId}` | 端口实例。同一资产放两份时端口 id 相同，必须带实例前缀 |
| `clipRef` | `{assetId}#{机位}:{动作}` | 片段身份，验收 3 的计数单位 |
| `bindings` | `{assetId -> entityId}` | 实例绑定表（§4.5），操作与高亮的解析依据 |

## 6. 步记录：过程的内核

与渲染无关的结构化数据，一次运行一份，落盘即冻结。

```
schemaVersion: 6
run:    { runId, kind, episode?, seed, rulesetVersion, engineHash, startedAt }
        # kind: explore（交互探索）| task（学员完成任务的运行，可判定）
        #      | production（拍片用的运行）
        # seed 仍记录（同一初始条件好复现现场），但不承诺两次跑出相同物理
steps:  [{
  i, t, phase, actor, causes,
  input, action, output,        # action 含工具名与完整参数
  tokens, ops, costMs,          # ops 见 §7.2 成本模型；costMs 仅供诊断
  world: { entities, highlight },
  caption, formula
}]
failures: [{ stepRef, failId, code, diagnosis }]
```

**唯一的权威：步记录本身**

| 角色 | 内容 |
|---|---|
| **权威** | 工具调用序列 + 参数 + 返回值 + 失败 |
| **不承诺** | 物理外观两次一致。同一份记录重跑，逻辑一样、画面可能略有差异（§7.1） |

判定的依据是这份记录，**不需要靠重跑世界来判定**。烘焙轨道（若制作侧用了）与 run 的关联记在制作侧产物清单里，不进 run 记录。

**契约**

| 项 | 规则 |
|---|---|
| 时间基准 | 只有 `t`（世界秒）；`costMs` 与 `ops` 不驱动画面 |
| `highlight` | 由 §4.4 的 `observe.targetRef` 解析后推导 |
| `causes` | 并行步可有多个前驱，顺序无关 |
| `code` | 取自状态层校验器枚举 |

**四条不变量**：渲染无关；一次运行一份且冻结；两个消费者（回放器读 `world`、图层渲染器读 `caption`/`formula`）共读一份；**判定不得依赖对初始条件敏感的量**（§7.1）。

## 7. 世界侧能力

### 7.1 物理：勉强好用就行

**标准**（用户裁决）：

> 项目需要的是一套**勉强好用**的物理，可以和《我的世界》《围攻》像。

即：不追求精确，不追求可复现，只要手感不崩——能推、能堆、能撞，东西不会莫名其妙穿模或抖得不像话。这两款游戏的刚体行为都不精确、也都不可复现，但玩起来没问题。

| 要 | 不要 |
|---|---|
| 方块能被推、被堆、被撞倒 | 精确的接触求解 |
| 传送带能把东西带走，卡住了看得出来 | 跨机器一致的结果 |
| 堆叠大致稳，倒下大致合理 | 逐帧可复现 |
| 实体数有上限、每帧有预算 | 真实材质、软体、布料 |

**run 的三种用途**

| kind | 用途 | 可否判定 |
|---|---|---|
| `explore` | 交互探索 | 否 |
| `task` | 学员完成任务的运行 | **是** |
| `production` | 拍片用的运行 | 否 |

**判定条件（替换此前那条"判定不读物理"）**

> **判定可以读物理，但不得依赖对初始条件敏感的量。**

区别很大：推倒那摞方块算过——可以；推倒与否取决于小数点后第六位——不行，那是任务设计得不好，学员学不到因果。这是设计准则，比确定性要求便宜得多。

**两类实体**（保留，但理由换了：不是为了确定性，是为了**逻辑可读**）

| 类别 | 谁决定位置与存在 | 物理能否移动 | id |
|---|---|---|---|
| **判定实体**（机器、闸门、计数目标） | 状态层（离散格点） | 原则上不；被推倒这类结果由事件上报处理 | `entityId` |
| **装饰实体**（碎屑、粒子、被推动的散块） | 物理 | 可以 | `fxEntityId` |

**接触怎么进逻辑**：物理层把接触这类事件**上报一次**给状态层，状态层据此改逻辑状态（单向、显式）。不再要求"由状态层按格点邻接自判"——那是为确定性付的代价，现在不需要。**保留的一条**：物理→逻辑的耦合必须单向且显式，不得依赖引擎副产品式的隐式耦合（红石的准连接性、0-tick 脉冲就是反面教材）。

**裁决**（替换原 spec §8.1）：

> **引入刚体物理引擎，标准是"勉强好用、手感对齐 MC 与围攻"。物理是世界的功能来源，不是画面装饰；不追求可复现，也不靠它保证跨机器一致；物理→逻辑单向且显式。**

**烘焙：按需可选，不再是全局必需**

`studio.bake` 保留，只在一种情况下用：**同一段画面要出两个机位并做剪辑拼接**（A 机位里手臂在左、B 机位里在右，剪在一起就穿帮）。默认路径不烘焙——一镜到底（相机在录制中自己推拉摇移）或录 wide 后期裁切，两种都不需要重跑物理。

**慢放仍不得放大物理步长**（理由从"确定性"换成"保真"）：放大步长会让东西穿透、堆叠炸开，画面变糙。《围攻》的实测就是这个现象。

**v6 删掉的东西**（v5 为确定性付的代价）：全量快照与 `stateHash`、`trackHash`、`sim.snapshot` / `sim.diff`、格点邻接自判接触、"判定 = 重跑记录"、隐性状态入档的强制要求。`world.snapshot()` 保留：它只取状态层，是学员与 agent 的日常工具。

**烘焙轨道的口径**（仅在用到时）：`motion/{runId}.bin`

| 项 | 口径 |
|---|---|
| 采样率 | 物理固定 dt；捕获按 25 fps 插值 |
| 记录对象 | 受物理影响的实体（装饰实体为主）；判定实体由状态层还原 |
| 内容 | 每帧每实体的平移与旋转，实体以 `entityId` / `fxEntityId` 标识 |
| 压缩 | 位置定点量化 + 差分；单集体积设实测上限 |
| 随机 | 随机源来自 run 的 seed |

### 7.2 工具面：三组

**世界工具**：`world.place` / `world.connect` / `world.set_param` / `world.run` / `world.inspect` / `world.snapshot`（只取状态层）

**可观测性工具**（红石的反面教训，进内核）：`world.read` / `world.trace` / `world.watch` / `world.step` / `world.diff` / `world.export_netlist`

每个端口明写语义（参照 ONI 的绿/红）；默认布尔，**模拟量做成连线上可见的显式端口类型**。

**文件与执行工具**（内置 agent 与学生共用，详见 `docs/10-契约/mini-codex.md`）：`fs.read` / `fs.write` / `fs.list` / `run.python` / `run.tests`

**工具与可视化载体的对应关系**（详见 `docs/10-契约/mini-codex.md` §2.3）：

> **一切修改走机械臂，一切读取走扫描器。**

| 载体 | 负责的工具 |
|---|---|
| 机械臂（接在 codex 末端的工具头） | `fs.write`、`world.place`、`world.connect`、`world.set_param` |
| 扫描器（同末端的另一只工具头） | `fs.read`、`fs.list`、`world.read`、`world.inspect`、`world.snapshot` |
| 执行器 | `run.python`、`run.tests`（其写回的文件仍由机械臂交付） |

读不留物、写留物，所以"它改了哪里"与"它读了什么"是两个不同性质的痕迹；两只工具头都可切换，切换动作本身可见。

**制作工具**（仅内容生产，不暴露给学员与 agent）：`studio.bake` / `studio.capture` / `studio.compose`

**学员的可搬运产出物**是**学员自己写的 MCP 工具定义与校验器**（原 spec §7 的红线）；`world.*` / `fs.*` / `run.*` 是平台侧接口，两者不是一回事。

**成本模型**（改造自《编程农场》的 200 : 1）：改世界与只读查询**定价不同**，且该数字**能被学员代码读到**，兼作优化指标、行为激励与步骤面板上的标量。落到已有口径：token 即电力，`ops` 是每步的可读计数。

**落位**沿用原 spec §8.4：MCP 客户端在 sidecar（Python 侧），Godot 不碰 MCP。

### 7.3 两次运行之间什么是稳定的

| 项 | 承诺 | 理由 |
|---|---|---|
| **逻辑** | 稳定。同一份步记录读两次，结论一致 | 教学正确性的地基：诊断题、两版对比、agent 评分全靠它 |
| **物理** | **不承诺**。同一份记录重跑，画面可能略有差异 | 这是换一套便宜、手感对的物理所付的代价（§7.1） |
| **LLM 响应缓存** | 键含规则集版本与提示词摘要 | 理由**是成本**，不是复现 |

**判定条件**（对原 spec §4.1 / §6 的修改）：判定只对 `kind: task` 的运行做，依据是它的步记录；**原 spec §4.1 的"给定随机种子回放，判定目标是否达成"改为当场判定**——不再依赖物理可复现。`explore` 与 `production` 永不参与判定。

## 9. demo 范围与验证

### 9.1 第一版 demo = 线性关卡链，终点是拼出一个自己的 agent

**用户裁决（2026-09-13）**：demo 阶段**抛弃网状教学**，改**线性关卡化教学**；同时提供自由沙盒；**一系列关卡的最终结果就是拼出一个 mini codex**（一个自己的小助手）。别的功能先不加。

| 项 | demo 的口径 |
|---|---|
| 教学组织 | **线性关卡链**，不是知识网导航。原 spec §5.4「网驱动，不是脊柱驱动」在 demo 阶段**不适用** |
| 终点产物 | 学员手里有**一个自己拼出来的 mini codex**：十四件组件齐备、能接任务、能跑、能导出 Python |
| 每关教什么 | 装上 2–4 件相关组件（见 §9.1.1），并引入 1–2 种新方块 |
| 自由沙盒 | **同时提供**，不受关卡约束；沙盒里可用已解锁的全部组件 |
| 微课 63 集 | 仍在，demo 阶段**不做批量**；每关是否配一段视频见开放问题 8 |
| demo 不做 | 网状导航、知识图谱界面、图谱驱动的推荐 |

**为什么这个终点是对的**：它把"理解 Agent 是怎么回事"变成一件能拿在手里看的东西——学员最后拥有的是**自己装的那台 agent**，而不是一堆做过的题。

**排除判据**（若某关要配视频才用得上）：写不出可判定的 `observe` / `fail`，**且**没有可拼的流程，则该集不进 demo。按此排除 10 集：E01、E02、E03、E07、E08、E09、E45、E61、E62、E63；E30 保留（"偏好数据收集"可判分），候选池 53 集。

### 9.1.1 五关的切法与各自的视频

用户裁决：**一关一组相关组件（约五关）**，**每关配一段视频**（3–5 分钟，从 63 集对应集剪）。

| 关 | 主题 | 装上的组件 | 配的视频 | 过关检查 |
|---|---|---|---|---|
| **L1** | 它是谁、接什么活 | 任务牌、角色铭牌 | **E49** 智能体身份与角色（必修） | 能给 codex 下一条任务，并看到它接下 |
| **L2** | 它怎么读、怎么写 | 文件柜、扫描器、机械臂 | **E51** 工具使用与调用优化（加考） | 能看到它读出指定文件、写出指定格子 |
| **L3** | 它记得住什么 | 上下文容器、记忆柜 | **E50** 记忆机制：显式与隐式（拓展） | 能看到它把上一次的结果带进这一次 |
| **L4** | 它怎么想、怎么决定 | 思考机、计划板、工具带 | **E40** 提示工程（必修） | 改它的提示，能看到计划随之变化 |
| **L5** | 它怎么跑完、怎么不错 | 回廊、执行器、校验门、旁路 | **E60** 程序填空与程序阅读拆解（专项） | 给它一个坏输入，它自己校验、重试、跑完 |

组件合计 2 + 3 + 2 + 3 + 4 = **14 件**，与 `docs/10-契约/mini-codex.md` 一致。

**每关的闭环**：看视频（3–5 分钟）→ 在工位把这一关的组件装上去 → 跑一遍 → 改一个参数 → 交 agent 五维评分（诊断，不给分）→ 下一关。

**终点**：五关走完，学员手里那台 codex 十四件齐备，能接任务、能跑、能导出 Python。自由沙盒全程可用。

**为什么按这个顺序**：先给它身份和活（L1），再给它手脚（L2），再给它记性（L3），再给它判断（L4），最后让它能自己跑完并兜住错（L5）。每一关都在前一层之上，且每关的产物马上能在下一关用上。

### 9.2 三个必须先测的数

| 测量 | 判定 |
|---|---|
| 单帧渲染耗时 | ≤0.5 秒按 25 fps；0.5–1 秒先试 25 fps 并记录余量；>1 秒在降帧补帧与并行渲染间二选一 |
| 烘焙耗时 + 轨道体积 | 单集轨道设体积上限，超限则减少受物理影响的实体 |
| 资产捕获的边际成本 | 用基础件拼一个新概念装置应在 30 分钟内完成 |

三个数都在 1920×1080 与最终光影配置下测。

### 9.3 demo 验收

1. **线性关卡链跑通**：五关（§9.1.1），每关装上 2–4 件组件并配一段视频
2. **终点产物**：一个可用的 mini codex——十四件组件齐备、能接任务、能跑、能导出 Python
3. **自由沙盒可用**：已解锁组件可在沙盒里自由拼装
4. **三个指示器都能跑**：跑到它了 / 可读取的文件 / 看出写了哪里
5. **agent 多维度评分**产出一次（维度见 `docs/10-契约/mini-codex.md` §4.1）
6. 12 种方块中至少用到 9 种
7. 三个测量数字落盘
8. 若某关配了视频：片段复用率适用 §1 验收 3
