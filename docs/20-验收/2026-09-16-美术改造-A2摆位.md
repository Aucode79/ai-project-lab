## 1. 复现：穿模是怎么来的

逐件量了"可见包围盒 / 载体碰撞盒 / 声明 footprint / 摆位 cell"四者（探针已随诊断删除）：

- **可见包围盒超过声明 footprint 的占多数**：`conc_loop_gallery` 深 +2.13 m、`mach_splitter` 宽 +1.25 m、
  `conc_thinker` 宽 +1.19 m（纸条与出料托盘伸到机身之外）……排布却按 footprint 估宽 → 必然叠。
- **载体碰撞体被截短**：`sandbox.gd` 把进深 `clampf(d, 0.5, 1.5)`，注释写明是为了"行距 1.5 m 相邻行不叠"——
  17/28 件的碰撞体比可见体小。这是**拿截短的碰撞体掩盖排布问题**，计划已判定不可接受。
- **深件被转 90°** 塞进行向，件与件的"朝向"因此不一致。
- 操作机位实拍（`A1/after_operate_dist11.png`）可见机器层层遮挡 + 28 张英文铭牌同时悬浮。

## 2. 改了什么（`game/scripts/sandbox/sandbox.gd`）

1. **占格按实测可见包围盒**，不再按声明 footprint：
   `占格 = ceil((实测 + 0.25) / 0.5)` 个标准方块；件居格中，所以相邻两件的可见体之间必留 ≥0.25 m。
2. **一律 `yaw = 0`**：同向是"坐标唯一确定"的前提，深件不再转 90°。
3. **行宽按台面形状算**：夯土台面是 L4 半径 `PAD_L4` 的圆角方，`x ≤ (p⁴ − z⁴)^(¼)` 减去边距；
   原实现写死"甲板 13 m"。
4. **按占格进深降序做 shelf packing**：同进深的件排进同一行，行带（按最深件算）才不浪费。
   排布顺序因此与资产枚举顺序解耦——世界侧的注册/放置另走一遍枚举顺序，实体编号稳定。
5. **碰撞体与基座都取实测范围，去掉 clamp**：排布已保证 ≥0.25 m 净距，碰撞体互不相压。
6. **视图平移到"可见包围盒中心落在刚体原点"**：偏心件（纸条/托盘）不再伸出自己的占格。
7. 铭牌高度取 `max(1.15, 件高 + 0.35)`：高件（任务牌 3.1 m）的牌子不再埋进机身。
8. 南侧工区（播放器/求助屏/三按钮/读数牌）整体南移 **z 5.5 → 7.0 m**，给生成台腾出两米。
9. **顺序铁律：先摆好位置，再 `add_child` 进树**（见 §3，这条修掉一个真 bug）。

占格的可视化：**基座（Plinth）现在就是"这件占了哪几格"**——用户要的"(x,y,z) 唯一确定"在画面上直接可见。
代价是基座面积比从前（footprint 大小）大，视觉份量变重（见 §5）。

## 3. 顺带修掉一个真 bug：传送带的带面会脱开机体

`AnimatableBody3D`（`mach_conveyor` 的带面，`sync_to_physics = true`）**进树那一刻会把自己的世界变换
当成绝对值交给物理服务器**；此后父节点再移动，服务器把节点局部变换"补偿"回去，带面就留在原地。

- **实测**：把载体先加进树（在原点）再摆到工位，带面的局部坐标被写成 `(2.5, −22.5, −1.75)`，
  即**落到世界原点**（`_probe_belt` 诊断，已随探针删除）。
- **原实现侥幸没暴露**：它是"先 `body.position = …` 再 `bench.add_child(body)`"，进树时父链已经在最终位置。
- **影响面**：不只是摆位。玩家**长按搬走一台传送带**时会移动父节点 → 带面同样会留在原地。
  也就是说这是一个既有的、可被玩家触发的缺陷（本轮只是把它从"偶发"变成"必现"才撞见）。
- **修法**：恢复并写死"先摆位、再进树"的顺序（`_add_workstation` ③ 的注释里说明理由）。
  量占格因此改走一个**临时挂点**：把视图放进 `MeasureHolder` 量完即弃，不拿真载体去量。

## 5. 仍未达成的口径（需要用户定范围）

1. **"所有资产都是方块组成"**：28 件里有 4 件含非方块网格 ——
   `l2_scanner`（`PlaneMesh`）、`conc_plan_board`（`PrismMesh`）、
   `conc_tool_belt`（`PrismMesh` + `CylinderMesh` + `TorusMesh`）、`player_screen`（2 个非方块）。
2. **"方向也一样"（指件内部）**：4 件含任意角旋转 ——
   `mach_splitter` 挡板 −45°、`l2_arm` 上臂/前臂 −32°/26°、`conc_thinker` 纸条 −12°、
   `conc_verify_gate` 侧条 −28.6° / 门臂 −18°。这些**在件内部**，摆位层面已经是同向的。
   其中机械臂的关节角属于"功能姿态"，是否也要方块化需要你定。
3. **声明 footprint 与几何不符（21/28 件）**：摆位已改用实测所以不再穿模，但 `assets/*/asset.yaml`
   与 `sandbox_assets.gd` 里的 footprint 仍是旧值；要不要按实测回写，涉及资产 yaml + 校验器。
4. **中央没有 6×6 m 留白**：28 件按实测占格铺开后基本占满台面（生成台 z ∈ [−8.5, 3.5]，x 约 ±9），
   计划 §5.1 要求的"中央 6×6 m 连续平面"与"28 件全摊在台面上"在本岛尺寸下不可兼得。
   可选：① 缩小陈列（部分件收进资产库面板）② 扩大岛/台面 ③ 接受无中央留白。
5. **基座变重的观感**：基座=占格之后，浅色台面上出现大片同色底片。若嫌重，可以改成
   "只描占格轮廓"或"只在选中时显示占格"（属于 A3/A5 的观感调整）。
