# 统一视觉角色验收

## 本轮改动

资产共享灰白机壳、深色结构、珊瑚执行、青绿信号与琥珀核心配色。新增 `asset_style.gd` 作为颜色角色真源，基础件、机械件、18 个关卡/展示组件、关卡配方和沙盒基座直接消费。成功/失败仍用独立颜色。

关卡平台由整面橙色改为中性色，移除旧版树和装饰粒子。沙盒保留岛体与暖草，降低饱和度和对比度，补足暗面。生成台基座改为哑光中性色。

28 件资产具有中文显示名，最多四张名称同时显示，并筛除画面边界外或互相重叠的名称。技术 ID、参数、端口、注册、编译和存档格式均未改。五个沙盒相机预设支持工作台与完整岛体构图；可选 `focus_offset` 随切换插值。

## 证据

派生截图与窗口验证脚本在 `game/shots/art-upgrade/A7/`，该目录沿用已有 ignore 规则。

| 文件 | 用途 |
|---|---|
| `before.png` / `after.png` | 1920×1080 同机位配色对照；拍摄于全景焦点调整之前，两张焦点一致 |
| `overview.png` | 最终全景，完整岛体构图 |
| `l1.png`～`l5.png` | 五关改造后的窗口截图，L1 为 1920×1080，其余为 1280×720 |
| `{iso,front,top,close,vista}_{1280,1920}.png` | 两种分辨率的五个沙盒预设 |
| `verify_presentation.gd` | 本轮窗口验证脚本，不修改已有测试文件 |

窗口验证命令：

```powershell
& tools/godot/Godot_v4.7.2-stable_win64_console.exe --path game --resolution 1280x720 -s res://shots/art-upgrade/A7/verify_presentation.gd
```

输出：`PRESENTATION: failures=0`，退出码 0。逐项核验 28 件显示名覆盖、两种分辨率下五个预设的焦点、最多四张名称、截图保存和全景到工作视角的动画切换。两个 close 机位均显示四张名称，其余预设为零。

## 自动测试

像素复核使用现有 `tools/measure_image.py` 与 Codex 随附 Python（系统 Python 缺 Pillow，未安装新依赖）：同机位前后饱和度均值 67.95 → 50.48，亮度均值 147.05 → 142.81，过曝像素 0.12% → 0.00%。最终全景和近景均非空白且过曝 0.00%；这些数值只记录调色变化，不代表审美评分。

第一轮 `bash tools/run_tests.sh`：`PASS=26 FAIL=0 SKIP=0`。

后续加入关卡地面与相机调整，同时进行窗口截图时，第二轮出现 L1 wiring T4 长按抓取失败，其余 25 项通过。停止截图后定向复跑 `--suite l1_wiring`：`PASS=4 FAIL=0 SKIP=0`（含三校验器）。尚不能仅据此断定失败由资源竞争导致；已有测试使用真实时钟与固定物理帧数，未修改测试或交互逻辑来规避失败。

停止窗口截图后，最终全量 `bash tools/run_tests.sh`：`PASS=26 FAIL=0 SKIP=0`，退出码 0。22 个 Godot 套件、三校验器与 check.sh 全部通过。`git diff --check` 退出码 0；本轮涉及的 GDScript 均保持 LF 且不超过 800 行。
