## 1. 目标与优先顺序

**核心美术目标：同时做到「正方体方块沙盒的结构辨识度」与「鲜明、独特的方块样式」。** 用户在 2026-09-16 补充强调：这是《Zoy》参考最值得学习的能力，应作为本计划的首要设计要求与验收标准。

《Zoy》的参考画面保留了清楚的立方体体块、格点堆叠、直角转折和阶梯关系，同时用圆钝边角、砖面分层、错缝、局部纹样、草顶收口与材质色差，让这些体块具有自己的样式。**结构保持方块性，表面与边缘具有设计性，两者必须在同一个对象上成立。** 此处借鉴的是视频中可观察的视觉结构，不据此认定《Zoy》具备自由编辑地形的沙盒玩法。

据此，把当前的「方块资产陈列台」改成有明确操作中心、具有手工玩具质感的箱庭实验室。方块本体的设计与场景构图同等重要；最终应在单块、连续拼接和整座场景三个尺度上，都能看到统一而独特的样式，并保留本项目的方块计量、机械运行与编程教学身份。

### 两项必须同时成立的要求

| 要求 | 具体含义 | 不通过的表现 |
|---|---|---|
| 正方体方块沙盒 | 基本占格与堆叠关系清楚；模块沿统一网格组织，平面、转角、台阶和凹口能读出方块构成 | 大范围圆化、连续曲面或装饰遮盖使方块单元难以辨认；为造型牺牲标准尺寸与拼装关系 |
| 独特样式效果 | 单个模块已有边角、表面、接缝与材质的设计；多个模块拼接后形成一致的建筑或机器样式 | 普通纯色立方体仅换颜色；主要辨识度依赖背景、草、灯光或后处理；单块细节与连续拼接互相冲突 |

给实现 agent 的具体要求是：**先证明“这一块本身就有设计，而且拼起来仍然是方块世界”，再把它扩展成完整箱庭。** 整理构图、减草和优化光照应帮助观众看清这一设计，不能替代方块本体的制作。

施工顺序：**基线与坐标正确性 → 灰模布局 → 代表性资产 → 材质与植被 → 光照 → 运行反馈 → 五关推广 → 完整验收**。前三项未过，不扩大资产数量，不靠 Bloom、景深或全局饱和度遮盖问题。

默认范围包括沙盒与 L1–L5，但先把沙盒的一小段完整操作区做成质量样板，再推广。bench 是历史测量环境，不作为改造目标。保持 Godot、Jolt、voxel 扩展和代码生成场景的现有路线；不引入开放世界、地形编辑、新玩法、昼夜循环或新渲染框架。

### 参考应转化为哪些制作要求

- 单独识别前景、操作主体和背景；高处、洞口、墙面与地面各有构图职责，不能用均匀铺满的碎细节代替空间设计。
- 方块应有大体块、边缘加工、表面图案三个层次。远景看轮廓，中景看倒角与砌筑，近景才读刻纹。
- 草、土、石、木、机器外壳应通过形状与受光表现区分。换几种颜色不能替代材质设计。
- 保留明亮环境中的暗面与接触阴影，让物体有厚度；控制高亮面积，先让操作对象清楚。
- 自然元素围绕实验室组织，装置应在这个场景里有支撑、朝向、通路和使用位置。
- 参考中的角色、标志、具体纹章、模型、贴图和音乐不进入游戏资产。装饰图案应围绕本项目的输入、加工、验证等概念原创。

## 4. 必须保留的契约与需要明确的规则

### 保留

- `STANDARD_CUBE_SIZE = 0.5 m` 是计量真源；token 本体不能缩放成不统一的大小。地形当前 1 m 体素相当于两个标准单位，不在本轮改分辨率。
- 端口 id、方向、位置语义，资产 id、参数键与 defaults，实体绑定，编译器输出，评分、存档与 MCP 行为保持一致。可见端口继续遵守半块网格。
- 主体占格、堆叠高度、物理形状和拾取范围必须能对应。视觉动画不能缩放或抖动碰撞体、端口和 token 计量体。
- 继续用第三人称轨道相机；正交、正视、俯视等是可切换预设。美术改造不把操作锁成宣传片机位。
- 保留全部资产的获取与操作能力；不为截图干净删除资产、停用真实运行或隐藏错误状态。

### P0 文档裁定：允许什么表面细节

现行 `方块体系.md` 的块状化 v2 比 AGENTS 中“工艺件豁免”的简写严格：可见零件也须入 0.25 m 格。现有沙盒倒角和自然装饰又已经采用更细尺寸。执行 agent 不得自行把所有装饰都视作豁免。

**建议采纳有限修订**：教学物件的占格外包络、独立零件尺寸/中心、端口、计量体保持现行规则；主体包络以内的倒角、刻纹、法线细节可采用更小尺度，不新增可计数零件、不改变堆叠面。非教学地景的草叶、叶簇、岩石另列为环境装饰，不能冒用教学方块身份。方轮规则本轮保留。

## 5. 美术规格

以下数值是首轮制作范围，必须在实际机位验证，不能当作参考原作的测量值。

### 5.1 空间与镜头

- 布局采用三个明确区域：中央可拼装工作区、两侧/后侧资产陈列区、外围自然景观。帮助屏与播放器有各自可到达且可阅读的位置。
- 中央先留出至少一块 6×6 m 的连续平面作为试作目标；真实操作所需空间不足时优先扩大工作面或调整陈列位置，不缩小 token 和机器。最终尺寸以全量资产包围盒排布验证为准。
- 高机器放后排、低矮件放前排。用实际包围盒确定排间距，初始净距取 0.5–1 m，再用拾取与连线操作校准。视觉槽位到 `state.place` 的 cell 映射同时核对，不引入取整后重合。
- 主操作平面先保持 y=23；台阶、断墙或高差放到外围。首轮不把可交互设备搬到多层平台，以免扩大物理与相机工作量。
- 全景须看到完整岛体与天空留白，主体不贴画框；工作镜头须能看清端口、活动部件和任务信息。全景不要求读所有小字。
- 先锁定全景、工作、材质近景、背侧四个对照机位。FOV 35–45° 可作为透视镜头起点；镜头距离以实际岛体包围盒和分辨率决定，不能照抄原作距离。
- 主工作镜头默认关闭景深；展示镜头仅允许外围轻微虚化。不能用模糊隐藏砖缝、重叠和错位。

### 5.2 色彩与照明

- 环境底色以低至中饱和砂灰、草绿和冷蓝阴影组织；珊瑚橙/青绿集中用于机器功能识别。不要把整片地板与操作机器涂成同样醒目的橙色。
- 保留现有资产类型颜色含义；环境草色避开端口、合法/错误等状态色的高亮表现。状态同时用形状、图标或动作区分，不能只靠红绿。
- 灰模和材质初校时先把全局饱和度、对比度恢复到中性附近，关 Bloom 与景深，固定曝光。先调材质本色，再调主光与补光，最后加后处理。
- 一盏主方向光确定体积与投影，天空/弱补光保住暗面；AO 只强调接触。主光相对工作机位取侧前方，需检查旋转到背侧仍能辨识组件。
- 金属只用于机械关节和少量嵌件；大面积外壳用哑光涂装。粗糙度初试：石土 0.8–0.95、外壳 0.55–0.8、金属嵌件 0.3–0.55；这些是待校准值。
- 发光只用于活动状态、端口或灯笼的小区域；草不靠强辉光争夺注意力。亮度/饱和度统计用于发现洗白、压黑等异常，**不再以“均值接近参考”认定画面达标**。

### 5.3 几何、表面与材质

- 按三层组织方块设计：第一层是稳定的正方体占格与拼接面；第二层是可见的边角加工、顶面收口和块间接缝；第三层是少量刻纹、色差与材质细节。第一层保证方块沙盒成立，后两层建立独特样式。
- 同一种模块分别检查孤立单块、连续地面、立墙、外转角、内凹角与台阶。边缘样式在拼接后应连贯，不能每块都套完整装饰框，拼成满屏重复格线。表面砖纹与实际占格边界需有清楚区别，教学计量块尤其不能因纹样产生数量歧义。
- 先做石质地景、草土顶块、机械外壳三类方块样板：共享边角尺度与细节密度，各自通过顶面/侧面关系、接缝和表面处理形成不同材质身份。机械外壳继续表达加工与装配特征，不能全部照搬砖墙纹样。
- 机器保留清楚的主块体，在表面修订获采纳后增加窄倒角、凹槽、面板层次。倒角先试边长的 2%–4%，取在包络内，不把每块变成圆团。
- 石砌采用错缝、大块分组和少量压纹；土、草皮和岩层分别处理。不要所有地形类型共用同一倒角与砖格视觉。
- 地面大面积保持安静，仅在边界、通路、机台底部出现少量结构线。工作区不铺高对比满屏网格；操作提示需要格线时局部显示。
- 图案只放在有意义的位置，例如输入口的箭头、验证门的检验章、记忆柜的档案符号。装饰花纹避开接口标识和文字。
- 中景纹样线宽以最终屏幕上约 2–4 像素可辨为目标；远景自然淡出。使用 mip/导数抗锯齿等现有渲染手段控制闪烁，不能靠无限加粗全距离常亮。
- 首轮沿用程序化 mesh 与 shader。只有代表资产证明程序化形体表达不足时，再提一项具体模型导入需求，说明成本与许可；不提前引入整套 DCC 管线。

### 5.4 植被与自然边界

- 草从连续高亮外圈改为疏密不同的片区，留出土面、低草和空隙。先把现有密度减到约一半做对照，再依据轮廓补回必要部分。
- 草高以 0.2–0.5 m 为常用范围起试，局部高草只在外围；近操作区的叶片不能遮挡端口、落点或说明牌。
- 草色先用根部暗绿、叶面灰绿、少量暖色梢；金黄可作局部季节色，不能整圈同亮。
- 树以树干、分枝方向和大小不同的叶簇建立轮廓，避免简单等大的球堆。布置 2–3 处不等重的树石组作方向锚点，不重复四角同款。
- 动态只保留低幅风摆、少量微粒和局部提示动效；工作区的静态信息优先于环境动效。

### 5.5 机器与文字

| 资产组 | 造型要求 |
|---|---|
| `base_block/track/container/gate/slot/wire/label` | 分别突出计量块、输送方向、容量开口、阻挡门、插入口、连接关系与牌面；不能全部变成有不同贴纸的盒子 |
| `mach_conveyor/splitter/stacker/counter/verify_gate` | 用运动部位和输入/输出方向解释功能；计数读数与验证结果要比装饰醒目 |
| `l2_file_cabinet/scanner/arm` | 柜体的取放口、扫描窗口、机械臂关节分别形成特征；读取和修改动作视觉上明确区分 |
| `conc_*` 与 `player_screen` | 按现有功能逐件设计：信息容器、规划牌、工具带、执行器、验证门、旁路、循环装置与图表均保留教学形状；求助屏和播放器继续分开 |

以 1280×720 的真实输出验读关键文字，建议有效字高不低于约 18 px；不能拿 `font_size` 参数直接当屏幕字号。长文本换行、限制牌面行数，优先沿用现有点按详情；不把求助改成新的 HUD 面板。

### 5.6 运行反馈

- 悬停：边缘或基座轻亮；选中：明确轮廓与端口提示；运行：当前机械部位移动；成功：短促回弹/小粒子；失败：停在失败组件并保留可读提示。
- 建议短反馈 0.12–0.25 秒、完成反馈 0.3–0.5 秒作为试作起点。禁止所有机器、草与标签同时持续弹跳。
- 动画挂在视图子节点上，由已有信号/状态触发；暂停、慢放、重新运行后不得残留错误发光或重复粒子。固定物理步长与现有时间控制契约保持不变。

## 7. 工程落点与实现注意事项

1. **砖纹坐标**：从 `vertex()` 明确传入世界坐标/世界法线 varying，或在 fragment 用正确的逆视变换恢复坐标；旋转、平移、不同 chunk 坐标都要检查。图案方向与用于受光的法线分开。不能再以“掩码总为零”为由永久绕过坐标问题。
2. **草法线**：需要世界向上时，将该方向转换到当前着色阶段的空间再混合；不随镜头旋转改变材质设计。动态视频验收不能仅依赖静帧。
3. **倒角成本**：先测当前真实渲染开销。若超过预算，保留主体外轮廓倒角，把非剪影表面交给材质；再评估面向暴露面的地形网格方案。不要一次给所有内部体素增加复杂几何。
4. **碰撞与布局**：先核对视图 AABB、载体碰撞、拾取代理、摆位 cell 的关系。地面用同一岛体形状作依据，核对中心、边缘、凹口及岛外；把碰撞箱“看上去差不多”视为未验收。
5. **共享范围**：已有 `asset_node.gd` 是多资产消费者的共享入口，可以在真实共用需要下扩展；不要新建泛化 services/utils/common。沙盒配方不反向依赖五关。触及 800 行上限先按已有模块职责拆分。
6. **资产总数**：`sandbox_assets.gd` 是当前 28 件枚举入口，历史注释中仍有“26 件”。执行时核对运行枚举、注册成功数和实际展示数；不能因布局行数不足而静默截断。
7. **新文件**：只允许有明确职责的美术资源、必要回归测试、验收报告；已有模块可承载的逻辑不另起包装层。新依赖需说明现有能力不足之处，本计划默认无需新增运行时依赖。
8. **文档冲突**：本计划不擅自覆盖现行规则。获采纳后同步美术方向、方块体系、相关 ADR 与 AGENTS 的过期简写；模块索引“世界配方唯一一份”与沙盒独立配方的矛盾也在涉及时修正。

## 8. 验收清单

### 视觉与交互

- **首要验收：方块结构与独特样式同时成立。** 提交普通立方体基线与样式方块的同尺寸、同机位、同光照对照；关闭景深、Bloom 与环境装饰，仍能明确指出边角、表面或接缝设计带来的差别，同时能看清原有占格与堆叠关系。
- 三类方块各交单块近景与组合样板：3×3 地面、三层台阶、包含内外转角的短墙；检查接缝连续性、纹样重复、转角收口与计量歧义。石/土/机械的样式可以不同，但方块尺度和整体精细程度须一致。只通过单块或只通过远景均不算完成。
- 沙盒四机位，L1–L5 至少各一个操作机位；1080p 作细节检查，720p 作可读性检查。不能只交全景海报。
- 关掉标签仍能通过轮廓区分样板机器的作用；打开任务信息后不与机器重叠。全景首先看到操作中心，草、灯柱、网格不抢主任务。
- 表面纹样随物体固定；环绕一周无明显游动、接缝跳变、树草闪烁或大面积曝光突变。
- 保留全部资产且均可拾取、拖放、配置、连线；验证阴影、植被与前排大件不会挡住操作反馈。
- 完成一次真实拼装运行、一次失败定位、一次保存/读取、一次 Python 导出；与改造前保持任务结果和导出语义一致。
- 录制 20–30 秒实际运行：环绕、缩放、拾取落地、运行、失败/成功、暂停恢复。允许演示片只覆盖一条流程，但另附全部关卡的操作检查结果。
- 做一次小规模可用性检查：让未参与实现的人指出当前操作对象、输入/输出与出错组件；记录实际困难，不用“像不像原作”单题代替功能验收。找不到试用者时明确列为待做，不能伪造结论。

### 性能

- A0 记录同一台机器的 GPU/驱动、分辨率、窗口模式、渲染后端、抗锯齿、VSync 与运行场景；A8 完全同条件复测。
- 预热后分别测静置、环绕、全资产运行三种工况各 60 秒，记录帧时间中位数/P95、draw calls、三角形、显存（能取得时）、载入至可操作时间；补记镜头切换和首次 shader 编译卡顿。
- **建议目标**：目标机 1080p 工作镜头达到 60 fps 级别；以 P95 帧时间 ≤16.7 ms 为目标。当前机器能否达到尚未测量，不能声称已有性能余量。
- 若目标机本来不达 60 fps，先实测并明确目标档位；至少以可用工作视图 P95 ≤33.3 ms 作为候选下限。未确定硬件前，该下限也不是已验收性能承诺。
- 阶段增量若让 P95 恶化超过约 10%，必须解释新增成本并决定取舍；不能用缩小窗口、少摆机器或隐藏草的特例替代正式对照。
