| 层 | 负责 | 状态 |

## 数据流（目标）

```
学员配置 ──► RuleSet（构建期冻结，可版本化）
                │
   每个 tick ────┼──► step(state, action) ──► (state', log)
                │            │
                │            └──► 一致性校验：不通过则拒绝并回滚
                │
                └──► LLM 响应缓存（键含 RuleSet 版本）→ 同 seed 可完全重放

呈现层 ◄── 状态流（HTTP/WebSocket）── 世界层
```

判定只对**状态层**做。LLM 产生的世界规则是开放的，但状态是结构化的，所以目标达成与否可判定。

## 关键决策

以下决策的完整理由在 spec 里，这里只列结论与影响：

1. **体素工厂形态**，不是纯 3D 星图。影响：呈现层要重做，旧的五屏降级为 overlay 面板。
2. **LLM 就是世界**，没有 NPC。规则由 LLM 在构建期生成一次并冻结，运行期多数 tick 不调模型。影响：世界层要引入 RuleSet 概念与版本化。
3. **学员写 Python**，机器接口走 MCP over stdio。影响：存在一条「可搬运性红线」——学员在沙盒里写的东西必须能直接搬进考场。
4. **不引入物理引擎**。工厂沙盒的底座是离散 tick 模拟，不是刚体物理。
5. **不引入 cordis / Node / DSH 作为宿主**。插件化走 Python 侧机制。
