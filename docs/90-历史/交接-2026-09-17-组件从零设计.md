## 1. 不变项（硬约束，设计不可触碰）

1. **世界度量**：标准方块 0.5 m，唯一来源 `game/scripts/asset_lib/asset_node.gd` 的 `STANDARD_CUBE_SIZE`；
   整件原点摆位 n×0.25 m；部件外延六面落 0.25 m 格点（回归锁 T7），部件中心可为 0.125 m 奇半格；主包络为 0.5 m 整数倍。语义「1 方块 = 1 个 token / 样本」——孩子数格子即知数量。
2. **几何**：可见几何一律 BoxMesh，旋转限 90° 整数倍；表面细节只有直切 45°×0.05 m 倒角一种（向内切、不改占格）；
   砖缝 / 花纹属材质层，不做几何。
3. **色彩**：现行调色盘 = `game/scripts/asset_lib/asset_style.gd` 的 11 角色
   （INK / STRUCTURE / SECONDARY / SHELL / PAPER / ACTION / SIGNAL / CORE / SUCCESS / ERROR / MUTED；
   语感：深墨字、深灰结构、灰白机壳、纸白读面、珊瑚=执行、青绿=信号、琥珀=核心发光、绿/红=成败）。
   新设计默认在此盘内工作；要扩盘需说明理由并交用户确认。
4. **交互语法**：长按=搬起、点按=打开详情、改参数=拖旋钮（不用键盘输数字）。
5. **教学地图**：`docs/10-契约/方块体系.md`、`concepts.yaml`（教什么不变；呈现方式属于本轮重设计范围）。
6. **引擎事实**：Godot 4.7.2；工程根 `game/`；场景由生成器脚本搭建（tscn 只挂根节点+脚本）；
   GDScript 一律 `preload`，不用 `class_name`。
7. **旧 28 件资产的设计已作废**，不作为参照（代码未删，后续按新设计分批替换；替换前旧件照常运行）。

## 2. 已认可方向（状态：全部「可修改」）

> 以下每条都在设计讨论中获得用户认可，但用户明示**全部可修改**——可以推翻重给，推翻时说明理由即可。

1. **俯视 2D 可读**：正俯视（顶视角）下整个游戏应读作 2D 游戏、体验不损；侧视是附加视角。
   组件允许高件与特色剪影——「形状帮助孩子识别部件」是明确诉求，不要为 2D 纯度压扁一切。
2. **信息面纪律**：流程信息（状态 / 流向 / 计数 / 进度）应在顶面可读；身份信息（名字 / 参数刻度）适合立面；
   点按出详情。
3. **世界内大屏**：镶嵌于地面、面积要大、可渲染视频（Godot 路线：SubViewport → ViewportTexture 贴地mesh）。
   曾讨论规格 16:9、约 14×7.9 m、与铺装齐平镶嵌 + 低框沿——数字与细节可改。用途示例：微课成片播放。
4. **世界内文字标准化为一类实体**：名字等文字由地面镶嵌小砖承载（曾讨论 0.5×0.25 m、纸白底暗色蚀刻），
   作为唯一合法的文字载体，全场统一、一处改样全场生效；悬浮文字标签已被否决（用户嫌丑）。
5. **退出沙盒 → 三栏应用壳**：按某键切换出应用级界面：左=历史对话列表 + 设置入口；中=沙盒世界
   （世界不暂停，继续运行）；右=对话框。右栏的对话对象=「世界管理者」——产品内置的最高级助手 Agent，
   无身体、只以 UI 形象出现（头像 / 签名 / 应答）。mini codex 自己的对话会话将来在同一左栏切换。
6. **三栏壳的 UI 配色搬现成方案**：DeepTutor 的 Cream / Dark 主题
   （`D:\DeepTutor\web\app\globals.css`：纸黄暖白底 `#fdfcf9` + 陶土 primary `#b0501e`，暗色为暖黑同族）。
7. **运行形象**：每个正在运行的 agent 会话（单线程）有一个可移动的 3D 形象；它走到哪台组件、
   哪台组件呈现「工作中」状态。曾认可草案：0.75 m 高、以标准方块为本体的会走造型、前端可挂可换的工具头、
   头顶身份标记（多智能体并存时区分会话）——此草案可修改。
8. **一切组件都是拼装积木**：可递归点开——点开一块，内部是更小块的拼接；
   **递归的底 = 一行 Python 代码概括成一块小积木**（积木的功能由那行代码决定）。
9. **世界地形**：开局一块尽可能广的平地，方便玩家建设；性能靠区块流式加载解决，不作为设计约束。

## 4. 代码结构清单（五子系统解剖事实，设计须逐条覆盖）

（file:line 均相对 `D:\smolagents\src\smolagents\`）

### 4.1 主循环（agents.py）
- `run()` 入口 agents.py:436；`reset` 参数 :440——默认 True=每次清空历史（一事一议）；
  False=同一会话连续对话（上下文跨轮保留）；每次 run 都重建系统提示 :477。
- ReAct 主循环 `_run_stream` :540——`while` 循环 + `max_steps` 步数上限（默认 20）。
- `interrupt_switch` 急停 :546——外部置布尔，下一圈生效。
- `planning_interval` 计划步 :550——第 1 步与每 N 步自动插入一次「重看计划」。
- `finally` 无条件入库 :594-604——失败的步骤也写进历史，错误文本变成提示回喂模型自纠；
  这是 agent 的自愈机制。超步数兜底 :810 带全部历史再调一次模型求「尽力答案」。
- `write_memory_to_messages` :758——历史**全量**拍平成消息发模型；没有滑窗 / 摘要 / 裁剪，
  唯一瘦身是单条观察写入时截断到 20000 字符（utils.py:254）。
- CodeAgent :1505 把「执行一段代码」伪装成一次名为 `python_interpreter` 的工具调用 :1715——
  代码型 / 工具型两类 agent 在主循环眼里同构。
- ToolCallingAgent :1215 支持一次产出多个工具调用、线程池并行执行 :1424 后汇合。

### 4.2 记忆与消息（memory.py）
- Step 家族：`ActionStep` :51（一步的 13 字段：步号 / 起止时间 / 发给模型的完整输入快照 / 模型原始输出 /
  模型文本 / 代码动作 / 工具调用列表 / 观察 / 观察图片 / 执行结果 / 错误 / token 用量 / 是否终点）、
  `PlanningStep` :154、`TaskStep` :187、`SystemPromptStep` :200。
- `AgentMemory` :214——只有系统提示 + 步骤列表两个字段；`reset` :232 只清步骤不清系统提示。
- token 计量 `TokenUsage`（monitoring.py:37：输入 / 输出 / 总量）。
- 错误步骤回放时自动附加「别重复错误，换思路重试」话术（memory.py:138）。

### 4.3 工具系统（tools.py / default_tools.py）
- `Tool` 基类五属性：name / description / inputs / output_type / output_schema（tools.py:131）——
  一个工具的全部自我描述。
- `@tool` 装饰器 :1061——普通函数凭类型注解 + docstring 自动生成 schema 并动态成类。
- 注册表 `{name: tool}`（agents.py:393）；`final_answer` 永远在列（default_tools.py:83）——
  「给出最终答案」本身也是一次工具调用，与其它工具同构。
- 参数校验 `validate_tool_arguments` :1361——未知工具 / 缺必填 / 类型不符分别报错。
- 工具两路注入：说明书渲染进系统提示（agents.py:652）+ 函数本体注入执行沙箱命名空间（executor :1763）。
- 工具输出包装 `ToolOutput`（agents.py:117）；返回图片 / 音频时存入 state 并给模型一句回执。
- 默认工具含：python 解释器、联网搜索、网页访问等（default_tools.py）。

### 4.4 执行器（local_python_executor.py）
- **不是 exec**：`ast.parse` 后用自写 AST 解释器逐节点求值（:1417，30+ 个 `evaluate_*`，
  未实现的语法直接拒绝）——「把代码拆开逐块执行」在代码里已字面存在。
- 命名空间三层查名 :847——state 变量 → 工具表 → 代码内自定义函数。
- `print` 被劫持进缓冲 :902——输出成为「观察」回喂模型，不进终端。
- 调用 `final_answer` = 抛 `FinalAnswerException` :1572（继承 BaseException，agent 代码里的
  `except Exception` 拦不住）——终点的特殊控制流地位。
- 执行错误包装带出错源码片段 :1655——模型直接看到哪一行炸了。
- 安全边界：import 白名单（11 个 stdlib，前缀树 :360）、危险模块 / 函数黑名单 :130、
  dunder 全禁；资源三闸——单步 1000 万节点求值 :1444、while 100 万圈 :457、30 秒墙钟 :285。
- 沙箱 state **跨步持久** :1716——上一步定义的变量留给下一步用，进程不重启。

### 4.5 模型层（models.py）
- `ChatMessage` 统一信封 :124（角色 / 内容 / 工具调用 / 原始响应 / token 用量）；5 种角色 :111。
- `OpenAIModel.generate` :1761——消息列表进 → 一次 HTTP → ChatMessage 出；
  token 从 `response.usage` 读（流式靠 `include_usage` 末包）。
- 消息清洗 `get_clean_message_list` :332——tool-call / tool-response 两种角色折叠成
  assistant / user、相邻同角色合并——「方言→标准语」的翻译层。
- 工具定义随**每次请求**整份下发（JSON Schema + `tool_choice`）:539——模型每步都收到完整工具菜单。
- 流式：delta 碎片按 index 归位、工具调用 arguments 逐字符累加 :220。
- 重试：只认 429 / 限流类错误，默认最多 3 次尝试（含初次），等待从 60s 起指数退避加抖动；参数 :38–41、装配 :1175–1178、判定 :1194。2026-09-18 源码复核校正，避免理解成额外重试三次。
