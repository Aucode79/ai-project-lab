## 2. 已定的设计

### 2.1 定位（依据 `覆盖矩阵.md`）

35 条**课程产品线**在第三、五、六、七、九章**没有一格覆盖**；第四、十一章在课程产品线里各只有 1 个覆盖，且一个来自政策纲要、一个来自免费公益课。愿意认真教 AI 的都是免费或进校线；付费主线是"编程语法骨架 + 定期插一个 AI 专题"。**机制类内容就是差异位。**

### 2.2 教学形态

- demo **抛弃网状教学**，改**线性关卡链**；知识网拓扑数据保留，但不作 demo 的导航
- 每关：看视频（3–5 分钟）→ 装上本关组件 → 跑一遍 → 改一个参数 → 交 agent 评分 → 下一关
- 三级粒度 = **折叠 / 展开**：一段流程折叠成一块 → 展开露旋钮 → 全展开成代码结构方块
- 自由沙盒全程可用

**五关**：

| 关 | 主题 | 装上的组件 | 视频 | 过关检查 |
|---|---|---|---|---|
| L1 | 它是谁、接什么活 | 任务牌、角色铭牌 | E49 | 能下一条任务并看它接下 |
| L2 | 它怎么读、怎么写 | 文件柜、扫描器、机械臂 | E51 | 能看它读出指定文件、写出指定格子 |
| L3 | 它记得住什么 | 上下文容器、记忆柜 | E50 | 能看它把上次结果带进这次 |
| L4 | 它怎么想、怎么决定 | 思考机、计划板、工具带 | E40 | 改提示能看到计划变化 |
| L5 | 它怎么跑完、怎么不错 | 回廊、执行器、校验门、旁路 | E60 | 给坏输入，它自己校验、重试、跑完 |

终点：五关走完，学员手里那台 codex **十四件齐备、能接任务、能跑、能导出 Python**。

### 2.3 方块体系：12 种

| 家族 | 数量 | 定形规则 | 性质 |
|---|---|---|---|
| 一 · 代码结构 | **1 种**（形状有直线/分岔/带环/扇出/汇聚五种拓扑变体） | 形状 = 流程拓扑 | 可操作、可拼装、**必须能导出 Python** |
| 二 · 非代码功能 | **11 种**：`chart_` `table_` `flow_` `text_` `concept_` `formula_` `timeline_` `dialogue_` `output_` `player_` `fallback_` | 形状 = 内容类型 | 只读或展示 |

分界规则：**能被学员写代码算出来的归家族一，只能读不能算的归家族二。**

三层资产库：基础件 `base_` → 机械 `mach_` → 概念装置 `conc_`（另加展示件与装饰件 `fx_`）。验收口径：用基础件 30 分钟拼出一个新概念装置。

### 2.4 这是一门语言，所以要有编译器

我们没设计新语言，但方块体系事实上是一门语言。抽象层级**在 Scratch 之上**：Scratch 是一积木一行（1:1），我们是一方块一个结构，一级预设装配 = 折叠的子网络。同类是 Simulink 的 Subsystem、Blueprints 的 Collapse to Function、Houdini 的 Subnet。

| 项 | 口径 |
|---|---|
| 输入 | **连接图 + 参数 + 装配层次** |
| **不读** | **位置与朝向**（同一份逻辑换摆法必须编译出同一份代码，否则教学会崩） |
| 输出 | 可搬运的**普通 Python**，不是自有 DSL（要能直接带进考场） |
| 编译期校验 | 端口类型匹配、必需端口未连接、参数越界、隐式依赖成环、循环必须有显式出口；**在拼装时即时反馈**（虚影变红就是它） |
| 折叠 | 头等操作：**同一个连接图，折叠层次不同，编译出的代码必须相同** |
| 双向 | 拼装→代码是主路径；代码→拼装**不做自动布局**，手改后标记「已脱离」，可主动「重排」（有损） |

### 2.5 物理与相机

**物理标准**：项目需要的是一套**勉强好用**的物理，像《我的世界》与《围攻》——不追求精确，不追求可复现，只要手感不崩（能推、能堆、能撞，不穿模不抖）。

| 要 | 不要 |
|---|---|
| 方块能推能堆能撞倒 | 精确接触求解 |
| 传送带能带走东西、卡住了看得出来 | 跨机器一致的结果 |
| 堆叠大致稳 | 逐帧可复现 |

**判定规则**：判定**可以读物理**，但**不得依赖对初始条件敏感的量**（推倒那摞方块算过可以；取决于小数点后第六位不行——那是任务设计得不好）。

**投放与状态层的接法**：虚影（松手后的落点预测）由物理前推算出；**落定那一刻上报一次**，状态层接管该格点，之后物理不再移动它。"可以往下丢"与"判定不读物理"能共存，靠的就是这一次上报。

**相机**：第三人称轨道相机为主，**相机自由换**（参考《围攻》）。预设位 `iso` / `front` / `top` / `close` / `vista`。播放 / 暂停 / 慢放 / 加速与相机并列。**慢放只靠取帧策略，绝不放大物理步长**（保真理由：放大后东西会穿透、堆叠炸开）。

**两次运行之间什么是稳定的**：逻辑稳定（步记录）；物理**不承诺**；LLM 响应缓存（理由是成本）。

### 2.6 mini codex：14 个组件

任务牌、角色铭牌、计划板、上下文容器、思考机、记忆柜、工具带、文件柜、执行器、校验门、旁路、回廊、机械臂、扫描器。

| 机制 | 口径 |
|---|---|
| **两只工具头** | **一切修改走机械臂，一切读取走扫描器**。读不留物、写留物——"它改了哪里"与"它读了什么"是两种痕迹 |
| **三个指示器** | 跑到它了（组件四态，相机跟着身子走）；可读取的文件（文件柜三格灯：可读/可写/禁读）；看出写了哪里（机械臂的落点与替换） |
| MCP | codex 是世界的另一个客户端，与学员共用同一套工具面，所以它的操作也落进同一份步记录 |
| 代做 | 全可代，但**代做运行不参与判定**，且慢速可视、随时接管 |
| 激励 | **五维诊断评分**（正确性/结构/效率/鲁棒性/可读性），给句子不给分数；**要用另一个实例评**，不能自己判自己 |
| 不设预算表 | 用量只进步记录，不在世界里显示 |

### 2.7 交互

**长按是搬，点按是开**：

| 手势 | 结果 |
|---|---|
| 长按 | 抓起物件进入拖拽，本体跟手抬起 + **虚影**标落点 |
| 点按 | **打开**它（看生成的代码 / 打开面板），打开后**占满全屏** |
| 鼠标移动 | 控制方向（视角朝向） |
| 右键拖动 | 控制摄像机位置（平移） |
| 滚轮 | 缩放 |
| 空格 | 单一运行键：跑 / 停 |
| `,` `.` | 前后十秒 / 单步前后；`Tab` 切预设位 |

- **虚影 = 物理落点预测**：松开手它会掉到哪、以什么姿态停住。**必须用同一套物理前推**，不能另写启发式——撒谎几次学员就不看它了
- **合法性是另一件事**：端口匹配、越界、重叠用颜色标，与"落在哪"分开表达
- **求助**：世界里**一大块求助屏**（不是 HUD）；**同一关失败 3 次**才给提示；提示用锚点气泡指到**具体那台组件**上
- **不做的交互**：弹窗评分与星星、排行榜、强制打卡、常驻代码编辑器、点错扣分、游戏内无提示、**导入标准答案/标准装置**、打卡返现、广告与购买弹窗、暂停视频提问
- **两条贯穿规则**：**界面上不放东西，世界里有东西**（预算表因此直接砍掉，不是缩小塞角落）；**一事一物**（机械臂/扫描器、播放器/求助屏）

### 2.8 生产管线

查映射 → 取/建资产 → 按需 studio.bake → studio.capture 出片段 → 排时间码 → 叠图层 → 配音合成 → 抽帧复核

| 测量 | 为什么 | 判定 |
|---|---|---|
| 单帧渲染耗时 | 决定成片产能（63 集 ≈ 66 万帧） | ≤0.5 秒按 25 fps；0.5–1 秒记余量；>1 秒在降帧补帧与并行渲染间二选一 |
| 烘焙耗时 + 轨道体积 | 决定改一次配置等多久、仓库装不装得下 | 单集轨道设体积上限 |
| 资产捕获的边际成本 | 决定三层资产库是否真的省 | 用基础件拼一个新概念装置应在 30 分钟内完成 |

**另有一个交互侧的数要早量**：拖动时每帧都要做一次落点前推预测，它直接占渲染预算。省法：预测降频（如 100 毫秒一次）、只在虚影会变时重算、前推用简化碰撞体。
