# 程序可视化设计交接

日期：2026-09-24。本文把程序盒、Python 语义表示、3D 视觉规则、用户选定的语句造型和当前实现状态交给后续设计与工程工作使用。文中的“已实现”描述源码或可运行原型；“目标”描述尚未完成的产品要求。

## 1. 产品目标

AI Project Lab 是一款面向青少年的 Agent 教育应用。学习者应先从可见的机器、材料、接口和通道理解程序，再逐层进入内部结构，最后才看到对应的 Python 语句。

程序编辑与学习过程必须留在同一个 3D 世界。不得把双击后的内容切成 2D 流程图、代码编辑器或另一个平面面板。相机靠近时应看到同一程序结构变大、变清楚；程序语义不应因远近切换成互不相同的摘要图。

画面中不放解释性文字、悬浮标签或文字工具栏。程序关系通过实体形状、接口和通道表达。到最底层时，原始 Python 语句可以作为唯一必要的文字，但也要依附在 3D 语句块或机器表面上，不能把学习者带回 2D 编辑器。

用户已认可沿用沙盒底部地形。程序机器应保持有立体感、轮廓简明、颜色对比清楚，并使用同一套空间与方块尺度规则。

## 2. 递归程序盒

程序由可以反复装入其他程序的 3D 盒子组成。视觉参照是 Fractal Foundry 的“盒子里能看见一幅小型内部构成”效果：重点不只是盒子有厚度，而是盒子顶面/内部要呈现一张一眼可辨的微缩 3D 场景。函数或模块是有名称、有输入输出接口的子工厂；父级程序中放的是这个子工厂的实例。

从盒子外面看，应能直接看到它内部的真实 3D 结构缩影，包括主要机器、通道和接口。这里的“缩影”不是截图、平面图标或代码标签。双击盒子后，相机沿同一套机器结构进入内部；盒中对象的身份、连接关系和交互规则保持一致。

盒子可以继续包含更小的盒子，直到内部主要流程足够简单。默认画面不逐个展开 token、标点或所有表达式节点。实现时应按学习目的聚合真实子图，不能用针对 Agent 或某类函数手工画的固定摘要取代程序本身。

## 3. 底层语义与可见原语

解析与执行需要稳定的语义结构；学习者看到的 3D 图形则是从这些结构投影出来的。两层不能混为一谈。

底层至少要保留模块与作用域、语义语句、表达式、符号、源码范围，以及数据和控制等关系。语义语句不是物理代码行：一个跨多行的调用仍可是一条语句；同一行的多个语句仍然是多个语义单元。赋值和返回节点可以引用独立表达式子图，数据边表达变量引用，控制边表达执行顺序。

默认可见块以完整的语义动作或一组紧密相关的行为为单位。表面可显示对应 Python 语句，但语义结构要能继续下钻。一个语句不应被拆成许多永远常驻的算子方块。

当前的语言无关视觉词汇如下：

| 视觉原语 | 对学习者的含义 | 常见 Python 结构 |
|---|---|---|
| `Object`（对象） | 可以在机器之间传递的值 | 数字、文本、列表、观测、工具结果 |
| `State`（状态仓） | 可以保存或更新值的位置 | 变量、对象属性、记忆、列表和字典 |
| `Transform`（变换机） | 把输入处理成输出 | 运算、普通函数、模型调用、工具调用 |
| `Router`（路由器） | 根据条件选择出口 | `if`、`elif`、`match`、异常分支 |
| `Repeater`（重复机构） | 按条件或项目重复处理 | `for`、`while`、重试和 Agent 循环 |
| `Channel`（通道） | 值、执行信号、事件或请求在结构间流动 | 数据边、控制边、调用、工具、文件、网络和事件关系 |
| `Group`（递归盒） | 给一块子图命名，并提供输入输出接口 | 函数、类方法、模块和可复用 Agent 组件 |

`Group` 是结构封装，不是额外的运行行为。`Channel` 是节点之间的关系，不要把它画成与处理机器同类的孤立方块。语法与图形不要求一一对应；只有源代码证据能支持的语义才可映射，无法判断时保留为通用操作或未识别副作用。

## 5. Python 语句造型选择

下表记录用户在 Python 语句三方案原型中的当前选择。字母指原型中 A、B、C 三个方案的编号。它们是已选定的视觉方向，不代表这些造型都已接入 Godot，也不改变 Python 语义。

| 代码类别 | 选择 | 选定造型与表达方式 |
|---|---|---|
| 赋值与状态更新 `assign` | B | **机器写入槽**：处理机将新结果压入固定状态槽，表现旧状态被新值更新。 |
| 表达式与函数调用 `expr` | C | **嵌套工厂盒**：盒内呈现缩小的真实 3D 子结构，双击沿同一结构进入。 |
| 返回 `return` | A | **出料滑道**：结果从函数盒侧面的出口离开。 |
| 条件选择 `if` / `match` | C | **分区路由盒**：盒内放置两条小型流程，由选中的一侧接通。 |
| 固定遍历 `for` | B | **步进托盘**：每次前进一格，把当前项目送到加工位置。 |
| 条件循环 `while` | A | **反馈传送带**：每轮输出回到条件检查口，通过后进入下一轮。 |
| 跳出循环 `break` | A | **循环出口坡道**：离开整个循环，并从循环后的语句继续。 |
| 跳过本轮 `continue` | B | **下一轮回送带**：跳过本轮余下步骤，返回 `for` 迭代器或 `while` 条件。 |
| 函数定义、调用与递归 `function` | A | **盒内缩影**：函数盒顶部显示内部 3D 结构，外部调用连接它的输入输出口。 |
| 异常 `try` / `except` / `raise` | B | **检测与接料**：检查站接住故障信号，再送到对应恢复机器。 |
| 资源作用域 `with` | B | **围合工作区**：资源与使用它的步骤在同一边界内，离开时执行清理。 |
| 类、实例与对象状态 `class` | C | **共享装配台**：多个同结构对象并列装配，各自保留独立状态。 |
| 模块导入 `import` | B | **吊运至模块架**：导入时装载模块并执行顶层代码；其中函数仍经接口调用。 |
| 断言 `assert` | C | **异常信号警报**：失败时发出 `AssertionError`，可被异常处理接住；未处理时终止当前流程。 |
| 等待结果 `await` | B | **并行线汇合**：其他工作可以继续，等待点在汇合处等待指定结果。 |
| 事件处理 `on_event` | A | **信号唤醒口**：事件从外部端口到达后启动对应处理步骤。 |
| 生成器 `yield` | C | **转盘取件**：每次取走一个结果后，转到下一个结果位置。 |
| 列表与容器 `list` | C | **扩展货架**：新增元素时向后增加格位，同时保留项目顺序。 |
| 聚合与归约 | A | **汇流加工**：多个值进入聚合机，输出总和或一个统计结果。 |
| 队列 `queue` | A | **先进先出通道**：值按进入顺序排队，先进入的值先被取出。 |
| 文件、网络与工具副作用 | A | **世界边界门**：机器穿过边界访问外部世界，再把实际回执带回来。 |
| 删除 `del` | A | **状态仓取出**：清空指定状态格，不影响其他格。 |
| 作用域 `global` / `nonlocal` | B | **分层状态仓**：模块级仓与外层函数仓分层；`global` 连模块仓，`nonlocal` 连最近外层函数仓。 |
| 空操作 `pass` | B | **空接口位**：只在编辑时显示可填入行为的接口，运行视图不占位。 |

这组选择在组合关系上保持一致：赋值与删除作用于状态仓；`for` 和 `while` 都使用重复结构，但各自显示项目步进或条件回流；`break` 和 `continue` 分别表示离开循环与进入下一轮；普通函数与外部副作用使用不同的盒子边界；`assert` 产生的异常可以进入异常处理结构；事件到达、等待结果和队列存取仍是不同关系。
